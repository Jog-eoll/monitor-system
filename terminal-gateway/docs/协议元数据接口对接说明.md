# 协议元数据接口对接说明

## 1. 目标

平台需要知道解密网关当前支持哪些厂商、型号、协议能力、控制指令和参数结构，用于做设备型号映射、指令页面配置和生产交付校验。

本次改造不修改现有发布、预检、控制指令接口契约，只新增只读查询接口。

## 2. 边界

- 解密网关是协议能力的权威源。
- 加密网关只做只读代理，不维护第二份协议能力映射。
- `gateway-device-protocol` 不改动，协议能力来自已装配的 `VendorProtocolAdapter`。
- 老接口继续保留：
  - `POST /api/client/publish/precheck`
  - `POST /api/client/publish/execute`
  - `POST /api/client/commands/execute`
  - `POST /api/secure-delivery/tasks`
  - `POST /api/secure-command/publish`
  - `POST /api/secure-command/control`

## 3. 解密网关接口

```http
GET /api/device-protocol/metadata
GET /api/device-protocol/metadata?vendor=QINGSONG
GET /api/device-protocol/metadata?vendor=NOVA_VIPLEX
GET /api/device-protocol/metadata?vendor=COLORLIGHT
```

示例：

```bash
curl "http://192.168.113.11:8093/api/device-protocol/metadata?vendor=QINGSONG"
```

## 4. 加密网关代理接口

```http
GET /api/secure-delivery/device-protocol/metadata
GET /api/secure-delivery/device-protocol/metadata?vendor=QINGSONG
```

兼容简短路径：

```http
GET /api/device-protocol/metadata
GET /api/device-protocol/metadata?vendor=QINGSONG
```

示例：

```bash
curl "http://192.168.113.10:8092/api/secure-delivery/device-protocol/metadata?vendor=QINGSONG"
```

加密网关读取现有配置：

```yaml
secure-delivery:
  terminal-gateway-url: "http://192.168.113.11:8093"
  terminal-http:
    connect-timeout-ms: 5000
    read-timeout-ms: 10000
```

## 5. 返回结构

外层仍使用项目统一 `Result`：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "metadataVersion": "1.0",
    "source": "terminal-gateway",
    "generatedAt": 1780000000000,
    "filter": "QINGSONG",
    "matched": true,
    "vendors": []
  },
  "timestamp": 1780000000000
}
```

`vendors[]` 字段：

| 字段 | 含义 |
| --- | --- |
| `vendorCode` | 解密网关内部厂商枚举，例如 `JET_FILE_II_STANDARD` |
| `vendorName` | 厂商/协议显示名 |
| `aliases` | 调用方可传入的厂商别名 |
| `productCode` | 建议平台保存的型号编码 |
| `productName` | 建议平台展示的型号名称 |
| `defaultPort` | 默认设备端口 |
| `transportType` | 底层通道类型，`UDP` / `HTTP` / `NATIVE_SDK` |
| `discoveryMode` | 发现方式 |
| `authMode` | 设备侧认证方式 |
| `adapterAvailable` | 当前运行包中是否已装配该适配器 |
| `controlCommands` | 可对接的控制指令和参数结构 |
| `capabilities` | 底层能力清单 |

## 6. 控制指令参数

接口会按当前适配器能力返回可用指令，不支持的指令不会出现在对应厂商的 `controlCommands` 中。

生产最小闭环指令：

| command | 参数 |
| --- | --- |
| `QUERY_STATUS` | `{}` |
| `BRIGHTNESS` | `{"brightness": 0..100}` |
| `BLACKOUT` | `{"enabled": true}` 或 `{"enabled": false}` |
| `REBOOT` | `{}` |
| `TIME_SYNC` | `{"time": "2026-07-03T10:00:00+08:00"}`，可省略 |

生产建议预留指令：

| command | 参数 |
| --- | --- |
| `NTP_SET` | `{"ntpServer": "192.168.113.10"}`，兼容 `server` |
| `DEVICE_IP_SET` | `{"ip": "192.168.113.239", "mask": "255.255.255.0", "gateway": "192.168.113.1", "dns": "192.168.113.1"}`，兼容 `netmask` / `subnetMask` |
| `SCREEN_ATTRIBUTE_SET` | `{"width": 96, "height": 36, "xCount": 1, "yCount": 1, "portNumber": 1}` |

扩展运维指令：

| command | 参数 |
| --- | --- |
| `FONTS_GET` | `{}` |
| `FONTS_SYNC` | `{"jetFileIIFonts": ["SimSun"]}` 或 `{"novaStarFonts": ["SimSun"]}` |
| `AP_NETWORK_SWITCH` | `{"enable": true}`，兼容 `enabled` / `on` |

## 7. 联调验证

1. 先验证解密网关：

```bash
curl "http://192.168.113.11:8093/api/device-protocol/metadata?vendor=QINGSONG"
```

2. 再验证加密网关代理：

```bash
curl "http://192.168.113.10:8092/api/secure-delivery/device-protocol/metadata?vendor=QINGSONG"
```

3. 如果加密网关返回 `503 TERMINAL_GATEWAY_UNREACHABLE`，优先检查：

- `secure-delivery.terminal-gateway-url`
- 解密网关 `8093` 是否启动
- 加密网关容器到解密网关 IP/端口是否可达

## 8. 兼容性结论

该接口是只读新增接口，不改变现有下发链路。平台可以先用它做厂商/型号/协议字段映射，原有青松发布、预检、控制接口不需要调整。
