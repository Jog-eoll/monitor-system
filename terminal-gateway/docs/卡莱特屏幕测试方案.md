# 卡莱特屏幕测试方案

## 1. 测试目标

验证卡莱特 `ColorLight` 屏幕在新改造解密网关中的协议能力、设备发现、控制指令和内容发布链路。

重点验证：

1. 解密网关能识别 `COLOR_LIGHT_STANDARD` 协议能力。
2. 卡莱特屏幕可通过 HTTP/TCP 探测或手动注册进入设备表。
3. 控制指令能经客户端、加密网关、解密网关同步返回最终结果。
4. 内容发布可使用同一套客户端发布接口，只要求节目单回调返回卡莱特目标信息。

## 2. 环境变量

按现场实际环境替换下表：

| 变量 | 示例值 | 说明 |
| --- | --- | --- |
| `CLIENT_BASE_URL` | `http://192.168.113.80:7081` | 客户端服务地址 |
| `PUBLISH_GATEWAY_URL` | `http://192.168.113.10:8092` | 加密网关地址 |
| `TERMINAL_GATEWAY_URL` | `http://192.168.113.11:8093` | 解密网关地址 |
| `PROGRAM_BASE_URL` | `http://192.168.113.123:3225` | 节目单回调服务地址或测试桩地址 |
| `SCREEN_IP` | `192.168.113.181` | 卡莱特屏幕 IP |
| `SCREEN_PORT` | `8989` | 卡莱特默认 HTTP 端口 |
| `MODEL_CODE` | `A2K` | 卡莱特主控设备型号；平台型号映射应指向 `COLORLIGHT` / `8989` |
| `VENDOR_HINT` | `COLORLIGHT` | 可用别名：`COLORLIGHT`、`COLOR_LIGHT`、`COLORIGHT` |

PowerShell 可先设置变量：

```powershell
$CLIENT_BASE_URL = "http://192.168.113.80:7081"
$PUBLISH_GATEWAY_URL = "http://192.168.113.10:8092"
$TERMINAL_GATEWAY_URL = "http://192.168.113.11:8093"
$PROGRAM_BASE_URL = "http://192.168.113.123:3225"
$SCREEN_IP = "192.168.113.181"
$SCREEN_PORT = 8989
$MODEL_CODE = "A2K"
$VENDOR_HINT = "COLORLIGHT"
```

## 3. 前置检查

### 3.1 服务健康检查

```powershell
Invoke-RestMethod "$PUBLISH_GATEWAY_URL/api/secure-delivery/health"
Invoke-RestMethod "$TERMINAL_GATEWAY_URL/api/secure-command/health"
```

预期：

- 加密网关健康接口可用。
- 解密网关控制入口健康接口可用。

### 3.2 卡莱特协议元数据检查

```powershell
Invoke-RestMethod "$TERMINAL_GATEWAY_URL/api/device-protocol/metadata?vendor=COLORLIGHT"
Invoke-RestMethod "$PUBLISH_GATEWAY_URL/api/secure-delivery/device-protocol/metadata?vendor=COLORLIGHT"
```

预期：

- `matched=true`。
- `vendorCode=COLOR_LIGHT_STANDARD`。
- `defaultPort=8989`。
- `transportType=HTTP`。
- `adapterAvailable=true`。
- `controlCommands` 中至少包含当前适配器实际支持的控制指令。

如果 `adapterAvailable=false`：

1. 确认解密网关镜像是否包含 `gateway-device-protocol` 中卡莱特适配代码。
2. 确认 Spring 配置是否启用 `ColorLightAdapterConfig`。
3. 重新部署包含卡莱特适配器的解密网关镜像。

### 3.3 屏幕端口连通性

```powershell
Test-NetConnection $SCREEN_IP -Port $SCREEN_PORT
```

预期：

- `TcpTestSucceeded=True`。
- 如果失败，先处理屏幕 IP、端口、网段、路由、防火墙。

也可直接访问卡莱特设备 HTTP 接口，具体路径以现场设备固件支持为准：

```powershell
Invoke-WebRequest "http://$SCREEN_IP`:$SCREEN_PORT" -UseBasicParsing
```

## 4. 解密网关发现与注册

### 4.1 自动扫描

```powershell
Invoke-RestMethod -Method Post "$TERMINAL_GATEWAY_URL/api/devices/scan"
Invoke-RestMethod "$TERMINAL_GATEWAY_URL/api/devices"
```

预期：

- 返回列表中存在 `ip=$SCREEN_IP` 的设备。
- `vendor` 为 `COLOR_LIGHT`、`COLOR_LIGHT_STANDARD` 或同义字段。
- `online=true`。
- `capabilities` 与元数据接口返回基本一致。

### 4.2 手动注册兜底

如果自动扫描不稳定或屏幕所在网段不支持扫描，使用手动注册：

```powershell
$body = @{
  deviceId = $SCREEN_IP
  ip = $SCREEN_IP
  port = $SCREEN_PORT
  vendor = $VENDOR_HINT
  productType = $MODEL_CODE
  online = $true
} | ConvertTo-Json

Invoke-RestMethod -Method Post "$TERMINAL_GATEWAY_URL/api/devices/register" `
  -ContentType "application/json" `
  -Body $body
```

预期：

- 返回 `code=200`。
- `/api/devices` 中可查到目标 IP。
- `attributes.productType` 或等价字段可追溯到 `A2K`。
- 后续控制指令以 `target.ip` 作为稳定匹配条件。

## 5. 在线状态接口测试

```powershell
Invoke-RestMethod "$CLIENT_BASE_URL/api/client/info-board/status?ip=$SCREEN_IP&port=$SCREEN_PORT"
```

预期：

```json
{
  "ip": "192.168.113.240",
  "online": true
}
```

说明：

- 如果该接口当前只按解密网关探测结果判断，必须先保证解密网关 `/api/devices` 或探测接口能识别卡莱特设备。
- 如果返回 `false`，先直接测解密网关到卡莱特屏幕的端口连通性。

## 6. 控制指令测试

控制接口为同步等待最终结果：

```http
POST /api/client/commands/execute
```

### 6.1 查询状态

```powershell
$body = @{
  requestId = "REQ-CL-CMD-QUERY-0001"
  operatorId = "operator-001"
  target = @{
    ip = $SCREEN_IP
    port = $SCREEN_PORT
    vendorHint = $VENDOR_HINT
  }
  command = "QUERY_STATUS"
  params = @{}
} | ConvertTo-Json -Depth 10

Invoke-RestMethod -Method Post "$CLIENT_BASE_URL/api/client/commands/execute" `
  -ContentType "application/json" `
  -Body $body
```

预期：

- `success=true`。
- `accepted=true`。
- `status=SUCCESS` 或等价成功状态。
- `deviceResult` 为结构化结果，不应只返回 Base64。

### 6.2 亮度

```powershell
$body = @{
  requestId = "REQ-CL-CMD-BRIGHTNESS-0001"
  operatorId = "operator-001"
  target = @{ ip = $SCREEN_IP; port = $SCREEN_PORT; vendorHint = $VENDOR_HINT }
  command = "BRIGHTNESS"
  params = @{ brightness = 60 }
} | ConvertTo-Json -Depth 10

Invoke-RestMethod -Method Post "$CLIENT_BASE_URL/api/client/commands/execute" `
  -ContentType "application/json" `
  -Body $body
```

预期：

- 接口返回成功。
- 屏幕亮度变化可观察。

## 7. 内容发布测试

卡莱特内容发布仍走客户端统一发布接口，但节目单回调必须返回卡莱特目标信息。

### 7.1 节目单回调要求

测试桩或平台接口需要返回类似结构：

```json
{
  "code": 0,
  "message": "",
  "data": {
    "success": true,
    "playlistId": "CL-001",
    "target": {
      "deviceId": "192168113181",
      "ip": "192.168.113.181",
      "port": 8989,
      "vendorHint": "COLORLIGHT"
    },
    "items": [
      {
        "orderNo": 1,
        "fileName": "colorlight-test.bmp",
        "fileType": "image",
        "fileUrl": "http://192.168.113.123:3225/cache/colorlight-test.bmp",
        "durationSeconds": 5,
        "fileHash": "replace-with-sha256"
      }
    ]
  }
}
```

要求：

- `target.ip` 必须是卡莱特屏幕 IP。
- `target.port` 推荐 `8989`，除非现场设备端口不同。
- `target.vendorHint` 使用 `COLORLIGHT`。
- `fileUrl` 必须能被客户端下载。
- `fileHash` 必须与文件实际内容一致。

本地复用青松 mock 文件服务时，按卡莱特目标覆盖参数启动。脚本默认使用内置 64×64 BMP；如需发布本地真实图片，增加 `--file-path` 并同步设置对外文件名：

```powershell
python info-publish-client\docs\qingsong-mock-file-manager.py `
  --host-ip <客户端可访问的本机IP> `
  --screen-ip 192.168.113.181 `
  --screen-port 8989 `
  --vendor-hint COLORLIGHT `
  --file-name 45.BMP `
  --file-path "D:\广告屏相关资料\测试数据\01_天气图标\45.BMP"
```

启动后 `PROGRAM_BASE_URL` 使用 `http://<客户端可访问的本机IP>:8199`。

预期：

- `publishAllowed=true`。
- `target.vendorHint=COLORLIGHT`。
- `items` 非空。
- `publishPermit` 非空。

### 7.3 发布

```powershell

  sigmaBaseUrl = $PROGRAM_BASE_URL
  operatorId = "operator-001"
  target = @{
    ip = $SCREEN_IP
    port = $SCREEN_PORT

    clearBeforePublish = $true
    checkExistence = $true
  }

  -ContentType "application/json" `
  -Body $body
```

预期：

- `success=true`。
- `accepted=true`。
- `deliveryTaskId` 非空。
- 解密网关发布任务最终成功。
- 卡莱特屏幕显示测试图片。

## 8. 解密网关直接联调

如果需要绕过客户端和加密网关定位问题，先在解密网关侧验证设备是否能被匹配：

```powershell
Invoke-RestMethod "$TERMINAL_GATEWAY_URL/api/devices"
```

确认目标设备：

- `ip=$SCREEN_IP`。
- `port=$SCREEN_PORT`。
- `vendor=COLOR_LIGHT_STANDARD` 或等价值。
- `online=true`。
- `capabilities` 包含对应指令能力。

如果控制链路提示 `TARGET_NOT_FOUND`：

1. 先确认 `/api/devices` 是否有目标 IP。
2. 确认请求体 `target.ip` 与设备表 IP 完全一致。
3. 不依赖扫描得到的 MAC；卡莱特联调同样优先用 IP 作为稳定匹配标识。
4. 必要时重新手动注册。

## 10. 验收标准

| 项目 | 通过标准 |
| --- | --- |
| 元数据 | 卡莱特 vendor 元数据可查，`adapterAvailable=true` |
| 连通性 | 解密网关到屏幕 `8989` 可达 |
| 注册 | `/api/devices` 中存在目标 IP |
| 在线状态 | 客户端在线状态返回 `online=true` |
| 控制 | `QUERY_STATUS`、`BRIGHTNESS`、`BLACKOUT` 至少通过 |
| 运维能力 | `NTP_SET`、`TIME_SYNC` 按现场支持情况验证 |
| 发布 | 通过统一发布接口下发内容，屏幕显示测试图片 |
| 恢复 | 黑屏测试后必须恢复显示 |

## 11. 常见问题

| 问题 | 处理 |
| --- | --- |
| `adapterAvailable=false` | 镜像未包含或未启用卡莱特适配器，重新打包部署 |
| `TARGET_NOT_FOUND` | 设备表无目标 IP、端口不一致、请求体未传 `target.ip` |
| 扫描不稳定 | 使用手动注册，后续指令按 IP 匹配 |
| 控制成功但设备无变化 | 查卡莱特 HTTP 调用日志和抓包 |
| 发布失败 | 先验证节目单回调、文件下载、hash 校验，再查解密网关发布编排 |
| 端口不通 | 处理屏幕网络、端口、防火墙或设备 HTTP 服务状态 |
