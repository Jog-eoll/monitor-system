# 青松屏幕测试方案

## 1. 测试目标

验证青松 `JetFileII` 情报板在现有安全发布链路中的可用性：

1. 客户端、加密网关、解密网关服务均可达。
2. 解密网关能识别青松协议能力并发现/注册设备。
3. 客户端能通过青松回调接口获取节目单。
4. `precheck` 能签发发布许可。
5. 内容发布能经加密网关、解密网关下发到青松屏幕。
6. 控制指令能同步返回最终设备执行结果。

本方案不要求修改现有接口契约。

## 2. 环境变量

按现场实际环境替换下表：

| 变量 | 示例值 | 说明 |
| --- | --- | --- |
| `CLIENT_BASE_URL` | `http://192.168.113.80:7081` | 客户端服务地址 |
| `PUBLISH_GATEWAY_URL` | `http://192.168.113.10:8092` | 加密网关地址 |
| `TERMINAL_GATEWAY_URL` | `http://192.168.113.11:8093` | 解密网关地址 |
| `SIGMA_BASE_URL` | `http://192.168.1.168:8199` | 青松平台回调服务地址；本地联调可用 mock 文件服务 |
| `SCREEN_IP` | `192.168.113.88` | 青松屏幕 IP |
| `SCREEN_PORT` | `9520` | 青松 JetFileII 默认端口 |
| `VENDOR_HINT` | `QINGSONG` | 可用别名：`QINGSONG`、`JETFILEII`、`JET_FILE_II` |

PowerShell 可先设置变量：

```powershell
$CLIENT_BASE_URL = "http://192.168.113.80:7081"
$PUBLISH_GATEWAY_URL = "http://192.168.113.10:8092"
$TERMINAL_GATEWAY_URL = "http://192.168.113.11:8093"
$SIGMA_BASE_URL = "http://192.168.1.168:8199"
$SCREEN_IP = "192.168.113.88"
$SCREEN_PORT = 9520
$VENDOR_HINT = "QINGSONG"
```

本地没有青松 8199 文件服务时，可在客户端所在机器启动 mock：

```powershell
python info-publish-client\docs\qingsong-mock-file-manager.py --host-ip 192.168.1.168 --screen-ip 192.168.113.88
```

mock 默认监听 `0.0.0.0:8199`，提供 `/health`、`/api/v1/callback/program-by-ip?ip=...` 和 `/files/qingsong-mock.bmp`。`--host-ip` 必须填写客户端可访问的本机 IP，否则节目单中的 `fileUrl` 可能无法下载。

## 3. 前置检查

### 3.1 服务健康检查

```powershell
Invoke-RestMethod "$PUBLISH_GATEWAY_URL/api/secure-delivery/health"
Invoke-RestMethod "$TERMINAL_GATEWAY_URL/api/secure-command/health"
```

预期：

- 加密网关返回 `healthy=true`。
- 解密网关返回可用状态。
- 如果加密网关健康失败，先检查 `secure-delivery.terminal-gateway-url` 是否指向解密网关。

### 3.2 协议元数据检查

```powershell
Invoke-RestMethod "$TERMINAL_GATEWAY_URL/api/device-protocol/metadata?vendor=QINGSONG"
Invoke-RestMethod "$PUBLISH_GATEWAY_URL/api/secure-delivery/device-protocol/metadata?vendor=QINGSONG"
```

预期：

- `matched=true`。
- `vendorCode=JET_FILE_II_STANDARD`。
- `defaultPort=9520`。
- `adapterAvailable=true`。
- `controlCommands` 至少包含 `QUERY_STATUS`、`BRIGHTNESS`、`BLACKOUT`、`REBOOT`、`TIME_SYNC`。

### 3.3 网络连通性检查

```powershell
Test-NetConnection $SCREEN_IP -Port $SCREEN_PORT
```

说明：

- 青松 JetFileII 可能主要走 UDP 协议，`Test-NetConnection` 的 TCP 结果不作为最终判定。
- 最终以解密网关探测接口和控制/发布结果为准。

## 4. 青松节目单接口检查

青松当前提供按 IP 获取节目单接口：

```powershell
Invoke-RestMethod "$SIGMA_BASE_URL/api/v1/callback/program-by-ip?ip=$SCREEN_IP"
```

预期返回：

- `code=0`。
- `data.success=true`。
- `data.playlistId` 非空。
- `data.target.ip=$SCREEN_IP`。
- `data.target.port=9520`。
- `data.items` 至少 1 条。
- 每个节目项包含 `fileName`、`fileType`、`fileUrl`、`durationSeconds`、`fileHash`。

注意：

- `target.deviceId` 建议青松返回屏幕稳定标识。若设备注册表使用 MAC，发布链路仍应优先用 `target.ip` 匹配设备。
- 文件 URL 必须能被客户端所在机器访问。

## 5. 解密网关设备发现与注册

### 5.1 自动扫描

```powershell
Invoke-RestMethod -Method Post "$TERMINAL_GATEWAY_URL/api/devices/scan"
Invoke-RestMethod "$TERMINAL_GATEWAY_URL/api/devices"
```

预期：

- 列表中出现 `ip=$SCREEN_IP` 的设备。
- `vendor` 为 `JET_FILE_II` 或 `JET_FILE_II_STANDARD` 相关值。
- `online=true`。
- `capabilities` 包含发布和控制相关能力。

### 5.2 手动注册

如果扫描不稳定，使用手动注册。青松/JetFileII 在线注册会走真实协议注册流水线，内部执行 JetFileII 登录和设备信息读取；不能只把设备写入内存表。

```powershell
$body = @{
  deviceId = $SCREEN_IP
  ip = $SCREEN_IP
  port = $SCREEN_PORT
  vendor = $VENDOR_HINT
  online = $true
} | ConvertTo-Json

Invoke-RestMethod -Method Post "$TERMINAL_GATEWAY_URL/api/devices/register" `
  -ContentType "application/json" `
  -Body $body
```

预期：

- 返回 `code=200`。
- 响应和后续 `/api/devices` 列表中该设备 `online=true`。
- 响应和后续 `/api/devices` 列表中该设备 `loggedIn=true`。

失败处理：

- 如果返回 `code=500` 且消息包含 `JetFileII 登录或读取设备信息失败`，先检查设备 IP/端口、JetFileII 凭据、设备连通性和解密网关协议日志。
- 不要在 `loggedIn=false` 的状态下继续发布；发布编排会在清屏、上传或设置节目单步骤返回 `DEVICE_NOT_LOGGED_IN`。
- 如只需要预置离线设备记录，可显式传 `online=false`。该模式不会登录设备，不用于发布验收。

## 6. 在线状态接口测试

```powershell
Invoke-RestMethod "$CLIENT_BASE_URL/api/client/info-board/status?ip=$SCREEN_IP&port=$SCREEN_PORT"
```

预期：

```json
{
  "ip": "192.168.113.88",
  "online": true
}
```

如果解密网关探测可达但客户端返回 `false`：

1. 检查客户端外部 `application.yml` 中 `info-board.status.gateway-url` 是否指向解密网关 `8093`。
2. 检查客户端是否读取了外部配置。
3. 检查客户端日志中状态查询实际访问的 URL。

## 7. 预检接口测试

请求：

```powershell
$body = @{
  requestId = "REQ-QS-PRECHECK-0001"
  sigmaBaseUrl = $SIGMA_BASE_URL
  operatorId = "operator-001"
  target = @{
    ip = $SCREEN_IP
    port = $SCREEN_PORT
    vendorHint = $VENDOR_HINT
  }
} | ConvertTo-Json -Depth 10

Invoke-RestMethod -Method Post "$CLIENT_BASE_URL/api/client/publish/precheck" `
  -ContentType "application/json" `
  -Body $body
```

预期：

- `success=true`。
- `publishAllowed=true`。
- `checks.ukeyAuthenticated=true`。
- `checks.clientAuthenticated=true`。
- `checks.sigmaProcessBound=true`。
- `checks.gatewayReady=true`。
- `playlistId` 非空。
- `playlistDigest` 非空。
- `publishPermit` 非空。
- `target` 和 `items` 随响应返回。

失败定位：

| 现象 | 优先检查 |
| --- | --- |
| 获取节目单失败 | `$SIGMA_BASE_URL/api/v1/callback/program-by-ip?ip=$SCREEN_IP` |
| 网关链路不可用 | `$PUBLISH_GATEWAY_URL/api/secure-delivery/health` |
| 文件校验失败 | `fileUrl` 可达性、`fileHash` 是否匹配 |
| UKey 未认证 | 客户端 `/api/config/vauth`、平台 UKey 服务、证书路径 |

## 8. 内容发布接口测试

请求：

```powershell
$body = @{
  requestId = "REQ-QS-PUBLISH-0001"
  sigmaBaseUrl = $SIGMA_BASE_URL
  operatorId = "operator-001"
  target = @{
    ip = $SCREEN_IP
    port = $SCREEN_PORT
    vendorHint = $VENDOR_HINT
  }
  options = @{
    clearBeforePublish = $true
    checkExistence = $true
  }
} | ConvertTo-Json -Depth 10

Invoke-RestMethod -Method Post "$CLIENT_BASE_URL/api/client/publish/execute" `
  -ContentType "application/json" `
  -Body $body
```

预期：

- `success=true`。
- `code=ACCEPTED`。
- `delivery.deliveryTaskId` 非空。
- `delivery.status=SUCCESS`。
- `playlist.playlistId` 非空。
- `playlist.items` 包含实际图片。
- 青松屏幕最终显示新内容。
- 如果加密网关文件下载失败、投递失败、超时或状态查询失败，客户端主接口应返回 `success=false`、`code=DELIVERY_FAILED`。

需要排障时可继续查询：

```powershell
Invoke-RestMethod "$PUBLISH_GATEWAY_URL/api/secure-delivery/tasks/{deliveryTaskId}"
```

## 9. 控制指令测试

控制接口为同步等待最终结果：

```http
POST /api/client/commands/execute
```

### 9.1 查询状态

```powershell
$body = @{
  requestId = "REQ-QS-CMD-QUERY-0001"
  operatorId = "operator-001"
  target = @{
    ip = $SCREEN_IP
    port = $SCREEN_PORT
    vendorHint = $VENDOR_HINT
  }
  command = "QUERY_STATUS"
  params = @{}
} | ConvertTo-Json -Depth 10

Invoke-RestMethod -Method Post "$CLIENT_BASE_URL/api/client/commands/execute" `
  -ContentType "application/json" `
  -Body $body
```

预期：

- `success=true`。
- `accepted=true`。
- `status=SUCCESS` 或等价成功状态。
- 响应中包含结构化的 `deviceResult`。

### 9.2 亮度

```powershell
$body = @{
  requestId = "REQ-QS-CMD-BRIGHTNESS-0001"
  operatorId = "operator-001"
  target = @{ ip = $SCREEN_IP; port = $SCREEN_PORT; vendorHint = $VENDOR_HINT }
  command = "BRIGHTNESS"
  params = @{ brightness = 80 }
} | ConvertTo-Json -Depth 10

Invoke-RestMethod -Method Post "$CLIENT_BASE_URL/api/client/commands/execute" `
  -ContentType "application/json" `
  -Body $body
```

## 11. 验收标准

| 项目 | 通过标准 |
| --- | --- |
| 元数据 | 青松 vendor 元数据可查，能力列表非空 |
| 设备 | `/api/devices` 中存在目标 IP，且可被指令匹配 |
| 在线状态 | 客户端在线状态返回 `online=true` |
| 节目单 | 青松回调按 IP 返回节目单和图片 URL |
| 预检 | `publishAllowed=true`，返回 `publishPermit` |
| 发布 | 屏幕显示发布内容，任务状态成功或已接受 |
| 控制 | `QUERY_STATUS`、`BRIGHTNESS`、`BLACKOUT`、`TIME_SYNC` 至少通过 |
| 恢复 | 黑屏测试后必须执行 `BLACKOUT enabled=false` 恢复显示 |

## 12. 常见问题

| 问题 | 处理 |
| --- | --- |
| 解密网关找不到目标设备 | 优先确认 `target.ip` 是否与注册表 IP 一致；必要时手动注册 |
| 扫描偶发拿不到 MAC | 不用 MAC 作为联调主键，目标匹配优先使用 IP |
| 发布成功但屏幕无变化 | 检查 `fileUrl` 下载、图片格式、解密网关到屏幕抓包 |
| `gatewayReady=false` | 检查加密网关健康接口和 `terminal-gateway-url` |
| 控制指令返回成功但设备无变化 | 查解密网关 `control-tasks` 结果和 UDP 抓包 |
