# 加密网关一键部署运维手册

本文档用于指导运维人员在 Linux 服务器上部署和维护加密/发布网关 `publish-gateway`。部署包入口为 `install.sh`，核心安装脚本为 `stage2/install.sh`，运行形态为 Docker Compose + host network，包含本地 Redis、加密网关主服务、国密 SDK、证书、Sigma Play 安全包验签、secure-delivery、client-relay 和 MQTT Agent 配置。

> 适用对象：`publish-gateway/deploy-package` 离线部署包。
> 安全要求：不要把 SSH 密码、数据库密码、Redis 密码、MinIO 密码、MQTT 密码、UKey PIN、证书私钥或现场一次性凭据写入手册、日志、命令历史或交付包。

## 1. 服务器要求

| 项目 | 最低要求 | 推荐配置 | 说明 |
| --- | --- | --- | --- |
| 操作系统 | Linux x86_64 | CentOS 7+ / Ubuntu 20+ / Debian 10+ | 需要支持 Docker、host network 和 USB 设备挂载 |
| CPU | 2 核 | 4 核及以上 | 安全投递、内容解析、加密、文件下载和 MQTT 命令会占用 CPU |
| 内存 | 4 GB | 8 GB 及以上 | Java 服务默认资源较轻，现场大文件投递建议提高内存 |
| 磁盘 | 30 GB | 50 GB SSD 及以上 | 包含镜像、日志、Redis 数据、拒绝包记录和临时文件 |
| 权限 | root 或 sudo | root | 需要管理 Docker、host 网络端口、防火墙和 USB 设备 |

必须具备的软件：

```bash
docker --version
docker compose version || docker-compose --version
curl --version
openssl version
```

如果现场允许脚本安装 Docker，可在安装时增加 `--auto-install-docker`；如果现场已安装 Docker，不需要增加该参数。

## 3. 镜像和组件

部署包默认使用以下镜像：

| 镜像 | 默认标签 | 归档文件 | 用途 |
| --- | --- | --- | --- |
| `gateway-udp-proxy` | `1.0.0` | `images/publish-gateway.tar` | 加密网关主服务 |
| `redis` | `7-alpine` | `images/redis-7-alpine.tar.gz` | 本地 Redis 缓存 |

离线安装时必须提供镜像归档。联网环境如允许从镜像仓库拉取基础镜像，可在 `deploy.conf` 中设置：

```bash
PULL_PUBLIC_IMAGES=true
```

生产现场建议仍使用离线镜像归档，便于版本固定和回滚。

## 4. 端口和访问方向

| 方向 | 端口 | 协议 | 说明 |
| --- | ---: | --- | --- |
| 平台 / 客户端 -> 加密网关 | `8092` | TCP | HTTP 接口，承载链路配置、安全投递、控制任务、健康检查和诊断接口 |
| info-publish-client -> 加密网关 | `18092` | UDP | client-relay 中继入口，用于客户端到加密网关的 UDP 中继 |
| 加密网关 -> 解密网关 | `8093` | TCP | secure-delivery、控制任务和解密网关健康检查 |
| 加密网关 -> 管控平台 UKey 服务 | `8063` 或单体 `8080` | TCP | 证书校验、上线、心跳 |
| 加密网关 -> 管控平台设备服务 | `8062` 或单体 `8080` | TCP | 设备注册、设备状态 |
| 加密网关 -> 管控平台内容服务 | `8065` 或单体 `8080` | TCP | 内容上报、内容检测、发布清单记录 |
| 加密网关 -> 管控平台日志服务 | `8071` 或单体 `8080` | TCP | 诊断日志和链路日志上报 |
| 加密网关 -> EMQX | `1883` 或 `8883` | TCP | MQTT 注册、心跳、命令和回执 |
| 加密网关 -> MySQL | `3306` 或现场端口 | TCP | `udp_proxy_gateway` 业务库 |
| 加密网关 -> MinIO | 现场对象存储端口 | TCP | 内容和媒体文件上报 |
| 本机 Redis | `6379` | TCP | host network 本机 Redis，默认仅本机部署使用 |
| 同网段 mDNS | `5353` | UDP | 启用 JmDNS 自动发现时使用 |
| USB UKey | 非网络端口 | USB | 通过 `/dev/bus/usb` 和 `/sys/bus/usb` 挂载给容器 |

如果现场只使用 MQTT 主链路，网关仍建议开放 `8092/tcp`，用于健康检查、内网调试、客户端安全投递和手工降级排查。

## 5. UKey、证书和 SDK

加密网关需要国密 SDK、证书和安全包验签公钥文件：

```bash
ls -la lib/libvauthsdk.so
ls -la lib/libvauthpackbridge.so
ls -la certs/*_SIGN.cer
ls -la trust/*.pub
```

关键配置项：

```bash
VAUTH_MOCK_MODE='false'
VAUTH_DEVICE_TYPE='ukey'
VAUTH_PASSWORD='<现场UKey_PIN>'
VAUTH_AUTH_ID='<加密网关认证ID>'
VAUTH_SERVER_ID='<管控平台认证ID>'
VAUTH_UKEY_PATH='<加密网关UKey路径>'
```

如果启用 SVAC USB 模组物理在位门禁，需要设置：

```bash
VAUTH_SVAC_MODULE_REQUIRED='true'
VAUTH_SVAC_MODULE_DEVICE_PATH=''
VAUTH_SVAC_MODULE_VENDOR_ID='<USB厂商ID>'
VAUTH_SVAC_MODULE_PRODUCT_ID='<USB产品ID>'
VAUTH_SVAC_MODULE_SERIAL='<USB序列号>'
```

`docker-compose.yml` 已挂载：

```text
/dev/bus/usb:/dev/bus/usb
/sys/bus/usb:/sys/bus/usb:ro
```

现场排查 USB：

```bash
lsusb
ls -la /dev/bus/usb
docker exec gateway-udp-proxy ls -la /dev/bus/usb
docker exec gateway-udp-proxy ls -la /sys/bus/usb
```

## 6. 生成并填写配置文件

进入部署目录：

```bash
cd /opt/publish-gateway
cp stage2/deploy.conf.example deploy.conf
chmod 600 deploy.conf
vi deploy.conf
```

### 6.1 MySQL 配置

使用外部 MySQL 时：

```bash
DB_HOST='<MySQL地址>'
DB_PORT='3306'
DB_NAME='udp_proxy_gateway'
DB_USERNAME='<业务用户>'
DB_PASSWORD='<业务用户密码>'
DB_ROOT_PASSWORD='<root密码或留空占位>'
```

外部 MySQL 需要提前创建数据库，并手工执行：

```bash
mysql -h <MySQL地址> -P3306 -u<用户> -p udp_proxy_gateway < mysql/init/udp_proxy_gateway.sql
mysql -h <MySQL地址> -P3306 -u<用户> -p udp_proxy_gateway < mysql/init/mqtt_command_record.sql
```

如数据库已由既有部署初始化，重复执行前必须先确认表结构和数据。

### 6.2 Redis 配置

使用部署包本地 Redis 时保留：

```bash
REDIS_ENABLED=true
REDIS_HOST='127.0.0.1'
REDIS_PORT='6379'
REDIS_PASSWORD='<Redis密码>'
REDIS_DATABASE='2'
```

使用外部 Redis 时：

```bash
REDIS_ENABLED=false
REDIS_HOST='<外部Redis地址>'
REDIS_PORT='6379'
REDIS_PASSWORD='<外部Redis密码>'
REDIS_DATABASE='2'
```

注意：当前 compose 会以 host network 方式运行本地 Redis。若现场已有 Redis 使用 `6379`，要么改用外部 Redis，要么先调整现场端口策略。

### 6.3 MinIO 配置

```bash
MINIO_ENABLED=true
MINIO_HOST='<MinIO地址>'
MINIO_PORT='9000'
MINIO_ACCESS_KEY='<accessKey>'
MINIO_SECRET_KEY='<secretKey>'
MINIO_BUCKET='monitor-content'
```

加密网关上传桶和平台内容服务读取桶必须一致。若出现内容检测一直 pending，需要同时检查：

```bash
MINIO_BUCKET
MONITOR_CONTENT_URL
平台内容服务的 MINIO_BUCKET_NAME / CONTENT_MINIO_ENDPOINT
桶下载策略
```

### 6.4 管控平台地址

微服务标准部署：

```bash
MONITOR_HOST='<管控平台IP或域名>'
MONITOR_CONTENT_PORT='8065'
MONITOR_UKEY_PORT='8063'
MONITOR_DEVICE_PORT='8062'
MONITOR_LOG_URL='http://<管控平台IP或域名>:8071'
MONITOR_CONTENT_URL=''
CONTROL_PLATFORM_URL=''
```

如果需要完整 URL 覆盖：

```bash
MONITOR_CONTENT_URL='http://<管控平台IP或域名>:8065'
CONTROL_PLATFORM_URL='http://<管控平台IP或域名>:8063'
MONITOR_LOG_URL='http://<管控平台IP或域名>:8071'
```

单体/融合部署可把完整 URL 改为单体入口：

```bash
MONITOR_CONTENT_URL='http://<平台地址>:8080'
CONTROL_PLATFORM_URL='http://<平台地址>:8080'
MONITOR_LOG_URL='http://<平台地址>:8080'
```

完整 URL 覆盖项优先级最高；未配置完整 URL 时才按 `MONITOR_HOST` 和端口组合。

### 6.5 网关注册和 JmDNS

```bash
REGISTRY_CLIENT_ID='publish-gateway-001'
DEVICE_VERSION='1.0.0'
DEVICE_LOCATION='<现场位置>'
DEVICE_MANUFACTURER='<厂商>'
DEVICE_MODEL='<型号>'
DEVICE_REMARK='publish encrypt gateway'

PROVIDER_JMDNS_ENABLED='true'
PROVIDER_JMDNS_BIND_ADDRESS='<本机业务网卡IP>'
PROVIDER_JMDNS_ADVERTISE_HOST='<本机业务网卡IP>'
```

如果现场不使用同网段自动发现：

```bash
PROVIDER_JMDNS_ENABLED='false'
```

### 6.6 client-relay 配置

```bash
CLIENT_RELAY_ENABLED='true'
CLIENT_RELAY_PORT='18092'
CLIENT_RELAY_TRUSTED_IPS=''
CLIENT_RELAY_VERIFY_SIGNATURE='false'
CLIENT_RELAY_SIGNATURE_SECRET=''
CLIENT_RELAY_REJECT_DIRECT_UDP='false'
```

生产环境如果只允许指定客户端接入，应配置可信 IP：

```bash
CLIENT_RELAY_TRUSTED_IPS='192.168.1.168,192.168.1.169'
```

### 6.7 安全包验签配置

```bash
SECURE_PUBLISH_ENABLED='true'
SECURE_PUBLISH_TRUST_STORE_DIR='/opt/publish-gateway/trust'
SECURE_PUBLISH_TRUSTED_KEY_IDS=''
SECURE_PUBLISH_DEFAULT_KEY_ID='default'
SECURE_PUBLISH_VERIFIER_PUBLIC_KEY_PATH=''
SECURE_PUBLISH_PACKAGE_EXTENSIONS='tar,spkg,zip'
SECURE_PUBLISH_REQUIRE_AUDIT_PASS='true'
SECURE_PUBLISH_REQUIRE_CONTENT_ALLOW='true'
SECURE_PUBLISH_REQUIRE_NOT_EXPIRED='true'
SECURE_PUBLISH_MAX_PACKAGE_SIZE_MB='500'
SECURE_PUBLISH_ASSEMBLY_TIMEOUT_MS='120000'
SECURE_PUBLISH_STALE_GAP_MS='30000'
SECURE_PUBLISH_REJECTED_DIR='/opt/publish-gateway/secure-publish/rejected'
```

JPEG 单包验签：

```bash
SECURE_PUBLISH_JPEG_ENABLED='true'
SECURE_PUBLISH_JPEG_MODE='audit'
SECURE_PUBLISH_JPEG_REQUIRE_BLOCK='false'
SECURE_PUBLISH_JPEG_REQUIRE_SIGNATURE='true'
SECURE_PUBLISH_JPEG_REQUIRE_CONTENT_ALLOW='true'
SECURE_PUBLISH_JPEG_REQUIRE_NOT_EXPIRED='true'
```

### 6.8 secure-delivery 和解密网关地址

```bash
SECURE_DELIVERY_PERMIT_HMAC_SECRET='<发布许可HMAC密钥>'
SECURE_DELIVERY_TERMINAL_GW_URL='http://<解密网关IP>:8093'
SECURE_DELIVERY_LARGE_FILE_REF_ENABLED='true'
SECURE_DELIVERY_DOWNLOAD_TIMEOUT_MS='900000'
SECURE_DELIVERY_DOWNLOAD_MAX_FILE_SIZE_MB='2048'
SECURE_DELIVERY_ENVELOPE_ENABLED='false'
SECURE_DELIVERY_ENVELOPE_SCHEMA_VERSION='2.0'
SECURE_DELIVERY_TERMINAL_HTTP_CONNECT_TIMEOUT_MS='5000'
SECURE_DELIVERY_TERMINAL_HTTP_READ_TIMEOUT_MS='900000'
```

大视频默认使用 file-ref 清单模式，避免把大文件转成巨型 JSON。解密网关必须能访问 `files[].fileUrl` 指向的临时文件地址。

### 6.9 MQTT Agent

公网 1883 临时联调：

```bash
MQTT_AGENT_ENABLED=true
MQTT_BROKER_URL=tcp://<平台公网IP或域名>:1883
MQTT_USERNAME=publish-gateway-001
MQTT_PASSWORD=<平台MQTT_DEVICE_DEFAULT_PASSWORD>
MQTT_CLIENT_ID=publish-gateway-001
MQTT_TENANT_ID=default
MQTT_SITE_ID=site-001
MQTT_RECONNECT_INTERVAL_MS=30000
MQTT_COMMAND_DEDUP_TTL_MS=86400000
MQTT_DEDUP_CLEANUP_INTERVAL_MS=600000
MQTT_REGISTER_ENABLED=true
MQTT_REGISTER_ON_CONNECT=true
MQTT_REGISTER_INTERVAL_SEC=300
MQTT_REGISTER_SERVICE_NAME=publish-gateway
MQTT_REGISTER_HOST=<加密网关IP>
MQTT_REGISTER_PORT=8092
MQTT_HTTP_FORWARD_TIMEOUT_MS=15000
```

生产建议改为 TLS：

```bash
MQTT_BROKER_URL=ssl://<MQTT域名>:8883
MQTT_TRUSTSTORE_PATH=
MQTT_TRUSTSTORE_PASSWORD=
```

说明：

- `MQTT_TENANT_ID`、`MQTT_SITE_ID` 必须与平台一致。
- `MQTT_CLIENT_ID` 必须唯一，平台下发命令会路由到该 ID。
- 网关侧 `MQTT_PASSWORD` 使用平台侧 `MQTT_DEVICE_DEFAULT_PASSWORD`。
- 发布网关自应用 `/udp-proxy/config` 链路可能耗时，`MQTT_HTTP_FORWARD_TIMEOUT_MS` 建议保持 `15000`。

### 6.10 控制投递最终态轮询

```bash
CONTROL_DELIVERY_MQTT_FINAL_REPLY_POLL_INTERVAL_MS=1000
CONTROL_DELIVERY_MQTT_FINAL_REPLY_TIMEOUT_MS=60000
```

该配置用于 MQTT `CONTROL_DELIVERY` 命令：加密网关创建控制任务后，按任务最终态上报 `SUCCESS`、`FAILED`、`TIMEOUT` 或 `CANCELED`，避免把受理态误判为执行成功。

### 6.11 诊断和来源校验

```bash
DIAGNOSTIC_LOG_ENABLED=true
GATEWAY_DIAGNOSTICS_ENABLED=false
LOG_REPORT_TOKEN=
CLIENT_PORT=7081
CLIENT_VALIDATE_TIMEOUT_MS=2000
PER_PACKET_CLIENT_VALIDATION_ENABLED=false
```

`CLIENT_PORT` 应与 info-publish-client 实际 HTTP 端口一致。现场常用 `7081`。源码默认或部分模板可能出现 `7080`，部署时必须按现场实际覆盖。

### 6.12 系统网络变更

默认关闭：

```bash
SYSTEM_NETWORK_CHANGE_ENABLED=false
SYSTEM_NETWORK_CHANGE_ALLOWED_INTERFACES=
SYSTEM_NETWORK_CHANGE_ROLLBACK_DIR=/tmp
SYSTEM_NETWORK_CHANGE_COMMAND_TIMEOUT_MS=10000
```

启用前必须确认容器以 host network + privileged/root 运行，并配置网卡白名单。未经过现场演练不建议打开。

## 7. 部署前检查

在部署目录执行：

```bash
cd /opt/publish-gateway

ls -la install.sh docker-compose.yml application.yml
ls -la stage2/install.sh stage2/deploy.conf.example
ls -la images/publish-gateway.tar images/redis-7-alpine.tar.gz
ls -la mysql/init/udp_proxy_gateway.sql mysql/init/mqtt_command_record.sql
ls -la lib/libvauthsdk.so lib/libvauthpackbridge.so
ls -la certs/*_SIGN.cer
ls -la trust
```

检查端口：

```bash
ss -lntup | egrep ':8092|:18092|:6379|:3306'
```

检查外部服务连通：

```bash
curl -I http://<管控平台IP>:8065/actuator/health
curl -I http://<管控平台IP>:8063/actuator/health
curl -I http://<解密网关IP>:8093/actuator/health
```

如果平台走单体 `8080`，将上面的微服务端口改为单体入口。

## 8. 试运行检查

只做预检查并生成 `.env`：

```bash
bash install.sh --check --yes
```

验证配置但不启动容器：

```bash
bash install.sh --dry-run --yes
```

预期结果：

- 脚本可以加载 `deploy.conf`。
- 必填配置校验通过。
- Docker / Docker Compose 检查通过。
- 镜像归档检查通过。
- `.env` 已生成。
- `docker-compose.yml` 语法验证通过。

若本机没有 Docker，`--check` 也会失败；此时先安装 Docker 或在目标服务器执行。

## 9. 正式部署

执行：

```bash
cd /opt/publish-gateway
bash install.sh --yes
```

如需允许脚本自动安装 Docker：

```bash
bash install.sh --yes --auto-install-docker
```

如现场防火墙由统一策略管理，不允许脚本自动放行端口：

```bash
bash install.sh --yes --no-auto-firewall
```

部署过程主要阶段：

| 阶段 | 内容 |
| --- | --- |
| 加载配置 | 读取 `deploy.conf` |
| 自动生成密码 | 对占位密码生成随机值 |
| 校验配置 | 校验数据库、UKey、平台地址等必填项 |
| 检查系统资源 | CPU、内存、磁盘 |
| 检查 Docker | Docker Engine 和 Compose |
| 检查端口冲突 | 8092、18092、Redis 端口 |
| 检查交付文件 | 镜像、SQL、SDK、证书 |
| 生成环境变量 | 写入 `.env` |
| 验证 Compose | 执行 compose config |
| 配置防火墙 | 可选开放端口 |
| 准备运行目录 | logs、certs、trust、redis/data |
| 启动服务 | Redis 和加密网关 |
| 健康检查 | `/actuator/health` |
| 生成账户文件 | `account.txt` |

## 10. 部署后验收

### 10.1 容器状态

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
docker logs --tail=200 gateway-udp-proxy
docker logs --tail=100 publish-gateway-redis
```

### 10.2 健康检查

```bash
curl -sf http://127.0.0.1:8092/actuator/health
curl -sf http://<加密网关IP>:8092/actuator/health
```

预期返回包含 `UP`。

### 10.3 平台注册和 MQTT 在线

在平台侧检查设备列表和 MQTT 在线状态。网关配置应包含：

```bash
MQTT_CLIENT_ID=publish-gateway-001
MQTT_REGISTER_SERVICE_NAME=publish-gateway
MQTT_REGISTER_PORT=8092
```

常用非破坏性 MQTT 命令：

- `QUERY_STATUS`
- `NOOP`
- `ECHO`

### 10.4 secure-delivery 健康

```bash
curl -sf http://127.0.0.1:8092/api/secure-delivery/health
curl -sf http://<解密网关IP>:8093/actuator/health
```

### 10.5 UKey 和 SDK

```bash
lsusb
docker exec gateway-udp-proxy ls -la /dev/bus/usb
docker exec gateway-udp-proxy ls -la /app/lib
docker exec gateway-udp-proxy ls -la /app/certs
```

### 10.6 Redis

```bash
docker exec publish-gateway-redis redis-cli -a '<Redis密码>' ping
```

预期返回 `PONG`。

## 11. 日常运维命令

进入部署目录：

```bash
cd /opt/publish-gateway
```

服务管理：

```bash
docker ps | grep -E 'gateway-udp-proxy|publish-gateway-redis'
docker logs -f gateway-udp-proxy

docker stop gateway-udp-proxy
docker start gateway-udp-proxy
```

```bash
docker-compose -f docker-compose.yml ps
```

## 12. 数据库备份和恢复

备份：

```bash
mkdir -p backup
mysqldump -h <MySQL地址> -P3306 -u<用户> -p udp_proxy_gateway > backup/udp_proxy_gateway_$(date +%Y%m%d_%H%M%S).sql
```

恢复：

```bash
mysql -h <MySQL地址> -P3306 -u<用户> -p udp_proxy_gateway < backup/<备份文件>.sql
```

恢复前必须先确认目标库、时间点和业务窗口，必要时先做二次备份。

## 13. 升级流程

1. 备份当前配置和数据库：

```bash
cd /opt/publish-gateway
mkdir -p backup/$(date +%Y%m%d_%H%M%S)
cp -a .env deploy.conf docker-compose.yml application.yml backup/$(date +%Y%m%d_%H%M%S)/
mysqldump -h <MySQL地址> -P3306 -u<用户> -p udp_proxy_gateway > backup/$(date +%Y%m%d_%H%M%S)/udp_proxy_gateway.sql
```

2. 记录当前镜像：

```bash
docker images | grep gateway-udp-proxy
docker inspect gateway-udp-proxy --format '{{.Image}}'
```

3. 加载新镜像：

```bash
docker load -i images/publish-gateway.tar
```

4. 重启服务：

```bash
docker compose -f docker-compose.yml up -d publish-gateway
```

5. 验证：

```bash
curl -sf http://127.0.0.1:8092/actuator/health
docker logs --tail=200 gateway-udp-proxy
```

## 15. 常见问题

### 15.1 提示缺少 Docker 镜像

现象：

```text
缺少 Docker 镜像: gateway-udp-proxy:1.0.0
缺少 Docker 镜像: redis:7-alpine
```

处理：

```bash
ls -la images/publish-gateway.tar images/redis-7-alpine.tar.gz
docker load -i images/publish-gateway.tar
docker load -i images/redis-7-alpine.tar.gz
docker images | grep -E 'gateway-udp-proxy|redis'
```

### 15.2 端口被占用

检查：

```bash
ss -lntup | egrep ':8092|:18092|:6379'
```

处理：

- 如果 `8092` 被占用，先确认是否已有加密网关实例。
- 如果 `6379` 被占用，改用外部 Redis 或调整本机 Redis 策略。
- 如果 `18092` 被占用，修改 `CLIENT_RELAY_PORT` 并同步现场网络策略。

### 15.3 服务启动后立即退出

检查：

```bash
docker logs --tail=300 gateway-udp-proxy
docker inspect gateway-udp-proxy --format '{{.State.ExitCode}} {{.State.Error}}'
```

常见原因：

- MySQL 地址、库名、用户或密码错误。
- UKey 未插入或容器未识别 USB。
- SDK 动态库缺失或依赖库缺失。
- 证书文件缺失。
- `application.yml` 外置配置格式错误。

### 15.4 UKey 或 SVAC 模组异常

检查：

```bash
lsusb
ls -la /dev/bus/usb
docker exec gateway-udp-proxy ls -la /dev/bus/usb
docker logs --tail=300 gateway-udp-proxy | grep -iE 'ukey|vauth|svac|usb'
```

处理：

- 确认 `VAUTH_PASSWORD` 是 UKey/SDF SDK 密码，不是平台登录密码。
- 同机双 UKey 时，配置 `VAUTH_UKEY_PATH`、`VAUTH_UKEY_SN`、`VAUTH_UKEY_CER_SN` 或 `VAUTH_UKEY_CER_ID` 做绑定。
- 启用 SVAC 模组门禁时，至少配置设备路径、序列号或 vendor/product 之一。

### 15.5 MQTT 连接不上

检查：

```bash
docker logs --tail=300 gateway-udp-proxy | grep -i mqtt
nc -vz <EMQX地址> 1883
nc -vz <EMQX地址> 8883
```

配置核对：

```bash
MQTT_AGENT_ENABLED=true
MQTT_BROKER_URL=tcp://<平台公网IP或域名>:1883
MQTT_USERNAME=publish-gateway-001
MQTT_PASSWORD=<平台MQTT_DEVICE_DEFAULT_PASSWORD>
MQTT_CLIENT_ID=publish-gateway-001
MQTT_TENANT_ID=default
MQTT_SITE_ID=site-001
```

注意：

- 公网 1883 是明文，仅建议临时联调。
- 生产建议使用 `ssl://<域名>:8883`。
- `MQTT_CLIENT_ID` 必须与平台下发目标一致。
- 平台侧必须配置 `MQTT_DEVICE_DEFAULT_PASSWORD`，且禁止空密码。

### 15.6 平台下发无响应

检查：

```bash
docker logs --tail=300 gateway-udp-proxy | grep -iE 'mqtt|command|reply|forward'
curl -sf http://127.0.0.1:8092/actuator/health
```

处理：

- 确认平台下发目标是实际 MQTT clientId，不是链路节点逻辑 ID。
- 确认 `MQTT_HTTP_FORWARD_TIMEOUT_MS=15000`。
- 确认本地 HTTP 白名单允许目标接口。
- 用 `QUERY_STATUS` / `NOOP` / `ECHO` 先验证非破坏性命令。

### 15.7 secure-delivery 到解密网关失败

检查：

```bash
curl -sf http://<解密网关IP>:8093/actuator/health
docker logs --tail=300 gateway-udp-proxy | grep -iE 'secure-delivery|terminal|delivery'
```

处理：

- 确认 `SECURE_DELIVERY_TERMINAL_GW_URL='http://<解密网关IP>:8093'`。
- 确认解密网关能访问文件引用地址。
- 确认解密网关已启动且协议能力正常。

### 15.8 内容检测或 MinIO 失败

检查：

```bash
docker logs --tail=300 gateway-udp-proxy | grep -iE 'minio|content|detect|receive'
curl -sf http://<平台内容服务>:8065/actuator/health
```

处理：

- 确认 `MINIO_BUCKET='monitor-content'`。
- 确认平台内容服务读取同一个 bucket 和 endpoint。
- 确认 bucket 下载策略允许内容服务读取对象。

### 15.9 client-relay 无数据

检查：

```bash
ss -lunp | grep 18092
docker logs --tail=300 gateway-udp-proxy | grep -iE 'client-relay|relay'
```

处理：

- 确认 `CLIENT_RELAY_ENABLED='true'`。
- 确认客户端目标地址指向加密网关 `18092/udp`。
- 如果设置了 `CLIENT_RELAY_TRUSTED_IPS`，确认客户端源 IP 在白名单内。

### 15.10 远程修改系统 IP 无效

默认关闭：

```bash
SYSTEM_NETWORK_CHANGE_ENABLED=false
```

如需启用，必须先完成现场演练，并设置：

```bash
SYSTEM_NETWORK_CHANGE_ENABLED=true
SYSTEM_NETWORK_CHANGE_ALLOWED_INTERFACES='<允许修改的网卡名>'
```

未配置白名单时不建议启用。

## 16. 安全建议

- 公网 MQTT 联调可临时使用 `tcp://<公网IP>:1883`，正式环境改为 `ssl://<域名>:8883`。
- `1883/tcp` 只允许联调来源 IP 访问，联调结束后关闭。
- EMQX Dashboard `18083` 不要公网裸露。
- `.env`、`deploy.conf`、`account.txt` 权限保持 `600`。
- UKey PIN、数据库密码、MQTT 密码、MinIO secret 不写入文档和截图。
- `GATEWAY_DIAGNOSTICS_ENABLED` 默认保持 `false`，只在排查窗口临时开启。
- `VAUTH_PAYLOAD_DEBUG_LOG_ENABLED` 默认保持 `false`，避免日志泄露业务载荷。
- `SECURE_PUBLISH_REJECTED_DIR` 中可能包含被拒绝的业务包，按敏感文件管理。
