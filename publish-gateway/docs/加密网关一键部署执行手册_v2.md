2  安装包内容说明

安装包文件名为 publish-gateway-v1.0.0.tar.gz，解压后包含部署加密网关所需的全部文件和 Docker 镜像。下面逐一说明包内每个部分的作用。

3  解压与验证

3.1  解压文件

将安装包上传到服务器后，执行解压：

# 创建部署目录（可自定义路径）

mkdir -p /opt/publish-gateway



# 解压到部署目录

tar -xzf publish-gateway-v1.0.0.tar.gz -C /opt/publish-gateway --strip-components=2



# 进入部署目录

cd /opt/publish-gateway

3.2  验证文件完整性

解压后请执行以下命令逐项检查：

# 1. 检查核心文件

ls -la install.sh docker-compose.yml application.yml



# 2. 检查配置模板

ls -la stage2/deploy.conf.example stage2/install.sh



# 3. 检查 SDK 动态库

ls -la lib/libvauthsdk.so lib/libCommonLib.so



# 4. 检查证书文件

ls -la certs/*.cer



# 5. 检查数据库初始化脚本

ls mysql/init/    # 应有 1 个文件



# 6. 检查 Docker 镜像归档

ls images/*.tar   # 应有 publish-gateway.tar

如果以上任何一项检查失败，说明安装包不完整，请联系开发团队重新获取。

5  执行部署

5.1  预检查（可选但强烈建议）

先做预检查，确认配置无误但不实际启动容器：

bash stage2/install.sh --check

预检查会依次执行：加载配置 → 校验参数 → 检查硬件 → 检查 Docker → 检测端口冲突 → 检查交付文件 → 生成 .env → 验证 Compose。

如果有报错，根据提示修复问题后重新执行。

5.2  正式部署

确认无误后，执行正式部署：

bash stage2/install.sh

安装器会自动完成以下 14 个步骤：

8  常见问题排查

8.1  部署失败常见原因

问题：端口被占用

症状：安装器提示 "port XXXX is already in use"

解决：

# 查看占用端口的进程

ss -ltnp | grep <端口号>



# 或者修改 deploy.conf 中对应的端口号

vi deploy.conf

问题：Docker 镜像缺失

症状：安装器提示 "required image not found"

解决：

# 手动导入镜像

docker load -i images/publish-gateway.tar



# 或者允许从网络拉取（需联网）

# deploy.conf 中设置：

PULL_PUBLIC_IMAGES=true

问题：容器启动失败

症状：容器状态显示 Exited 或 Restarting

解决：

# 查看容器日志找出原因

docker logs gateway-udp-proxy



# 常见原因：

# - MySQL 连接失败：检查 DB_HOST、DB_PORT、DB_PASSWORD

# - UKey 未识别：检查 USB 设备是否正确挂载

# - 证书缺失：检查 certs/ 目录

问题：UKey 未识别

症状：日志显示 "UKey device not found" 或 "VAuth init failed"

解决：

# 1. 检查 UKey 是否插入

lsusb | grep -i ukey



# 2. 检查 USB 设备挂载

docker exec gateway-udp-proxy ls -la /dev/bus/usb/



# 3. 检查容器是否以 privileged 模式运行

docker inspect gateway-udp-proxy | grep -i privileged



# 4. 检查 UKey PIN 码是否正确

# 在 deploy.conf 中检查 VAUTH_PASSWORD 配置

问题：数据库连接失败

症状：日志显示 "Connection refused" 或 "Access denied"

解决：

# 1. 检查 MySQL 是否运行

systemctl status mysql



# 2. 检查数据库是否存在

mysql -h 192.168.1.31 -u root -p -e "SHOW DATABASES LIKE 'udp_proxy_gateway';"



# 3. 检查用户权限

mysql -h 192.168.1.31 -u root -p -e "SELECT user, host FROM mysql.user;"

问题：管控平台连接失败

症状：日志显示 "Connection refused to monitor-host"

解决：

# 1. 检查管控平台是否运行

curl http://192.168.1.233:8080/actuator/health



# 2. 检查网络连通性

ping 192.168.1.233



# 3. 检查防火墙

telnet 192.168.1.233 8080

问题：设备注册失败

症状：日志显示 "registry failed" 或设备在管控平台不可见

解决：

# 1. 检查 JmDNS 配置是否正确

grep PROVIDER_JMDNS deploy.conf



# 2. 检查本机 IP 是否正确

hostname -I



# 3. 检查管控平台设备服务端口

curl http://192.168.1.233:8080/actuator/health

8.2  EMQX 相关问题（MQTT 模式）

问题：MQTT 连接失败

症状：日志显示 "MQTT connection failed"

解决：

# 1. 检查 EMQX 是否运行

curl http://192.168.1.233:18083/api/v5/status



# 2. 检查 MQTT 端口是否监听

ss -ltn | grep 1883

ss -ltn | grep 8883



# 3. 检查 MQTT 配置

grep MQTT deploy.conf

8.3  服务器重启后

服务器重启后，Docker 容器会自动启动（配置了 restart: always）。如果服务未自动恢复：

# 手动启动所有服务

cd /opt/publish-gateway

docker-compose up -d



# 等待 30 秒后检查状态

docker ps | grep gateway-udp-proxy



9  升级与回滚

9.1  升级流程

升级时仅需替换对应服务的 Docker 镜像，然后重启：

# 1. 加载新镜像

docker load -i images/publish-gateway-new.tar



# 2. 重启指定服务

docker stop gateway-udp-proxy

docker rm gateway-udp-proxy

docker compose up -d gateway-udp-proxy



# 3. 或者重启全部

cd /opt/publish-gateway

docker-compose restart

9.2  回滚

如果新版本有问题，可以回滚到旧镜像：

# 1. 备份当前镜像

docker tag gateway-udp-proxy:1.0.0 gateway-udp-proxy:backup



# 2. 恢复旧镜像

docker tag gateway-udp-proxy:backup gateway-udp-proxy:1.0.0



# 3. 重启服务

docker-compose up -d

⚠ 建议在升级前备份数据库：

mysqldump -h 127.0.0.1 -P 3306 -u root -p udp_proxy_gateway > backup_$(date +%Y%m%d).sql
