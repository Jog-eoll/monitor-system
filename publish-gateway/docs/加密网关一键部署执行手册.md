# 加密网关（publish-gateway）一键部署执行手册

## 1. 部署前准备

### 1.1 服务器硬件要求

| 项目 | 最低要求 | 推荐配置 | 备注 |
|------|---------|---------|------|
| 操作系统 | Linux (CentOS 7+, Ubuntu 20+, Debian 10+) | - | 仅支持 Linux |
| CPU | 2 核及以上 | 4 核 | - |
| 内存 | 4 GB 及以上 | 8 GB | - |
| 磁盘 | 30 GB 及以上可用空间 | 50 GB SSD | - |
| 网络 | 固定 IP，能访问内网 | - | 需要连接管控平台 |

### 1.2 软件环境要求

- Docker Engine 20.10+（需提前安装）
- Docker Compose v2（docker compose）或 v1（docker-compose）
- curl、tar、openssl 命令可用
- 防火墙工具：firewalld / ufw / iptables 之一（可选）

### 1.3 硬件设备要求

- **UKey 硬件**：国密 UKey 设备（用于数据加密）
- **USB 接口**：服务器需要有可用的 USB 接口

### 1.4 需要开放的端口

| 服务 | 端口 | 协议 | 用途 |
|------|------|------|------|
| 加密网关 HTTP | 8092 | TCP | 管控平台配置下发、健康检查 |
| 客户端中继 | 18092 | UDP | 接收客户端数据 |
| Redis | 6379 | TCP | 缓存服务（本地部署时） |

### 1.5 外部依赖服务

| 服务 | 说明 | 是否必须 |
|------|------|---------|
| MySQL | 存储链路规则配置 | 是 |
| Redis | 内容缓存 | 是 |
| MinIO | 对象存储（可选） | 否 |
| 管控平台 | 设备注册、内容上报、UKey认证 | 是 |

### 1.6 部署前检查清单

| 序号 | 检查项 | 确认 |
|------|--------|------|
| 1 | 服务器硬件满足最低要求 | □ |
| 2 | Docker 和 Docker Compose 已安装并正常运行 | □ |
| 3 | UKey 硬件已插入服务器 USB 接口 | □ |
| 4 | MySQL 数据库已创建 `udp_proxy_gateway` 数据库 | □ |
| 5 | 管控平台已部署并可访问 | □ |
| 6 | 上述端口均未被其他程序占用 | □ |
| 7 | 安装包已上传至服务器 | □ |
| 8 | 已以 root 用户或 sudo 权限登录 | □ |

## 3. 解压与验证

### 3.1 解压文件

```bash
# 创建部署目录
mkdir -p /opt/publish-gateway

# 解压安装包
tar -xzf publish-gateway-deploy.tar.gz -C /opt/publish-gateway --strip-components=2

# 进入部署目录
cd /opt/publish-gateway
```

### 3.2 验证文件完整性

```bash
# 1. 检查核心文件
ls -la install.sh docker-compose.yml application.yml

# 2. 检查安装脚本
ls -la stage2/install.sh stage2/deploy.conf.example

# 3. 检查 SDK 动态库
ls -la lib/libvauthsdk.so

# 4. 检查证书文件
ls -la certs/*.cer

# 5. 检查 Docker 镜像
ls -la images/publish-gateway.tar

# 6. 检查 MySQL 初始化脚本
ls -la mysql/init/
```

如果以上任何一项检查失败，说明安装包不完整，请联系开发团队重新获取。

## 4. 配置部署参数

### 4.1 复制配置模板

```bash
cp stage2/deploy.conf.example deploy.conf
vi deploy.conf   # 或使用你喜欢的编辑器
```

### 4.2 必须修改的配置项

#### 4.2.1 MySQL 数据库配置

```bash
# MySQL 服务器地址
DB_HOST='192.168.1.31'
DB_PORT='3306'
DB_NAME='udp_proxy_gateway'
DB_USERNAME='root'
DB_PASSWORD='your_mysql_password_here'
```

**注意**：
- 需要提前在 MySQL 中创建数据库：`CREATE DATABASE udp_proxy_gateway CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`
- 如果密码包含 `Replace_` 前缀，安装器会自动生成随机密码

#### 4.2.2 Redis 配置

```bash
# Redis 服务器地址（使用外部 Redis 时修改）
REDIS_HOST='192.168.1.31'
REDIS_PORT='6379'
REDIS_PASSWORD='your_redis_password_here'
REDIS_DATABASE='2'
```

#### 4.2.3 管控平台配置

```bash
# 管控平台服务器地址
MONITOR_HOST='192.168.1.233'
MONITOR_CONTENT_PORT='8080'
MONITOR_UKEY_PORT='8080'
MONITOR_DEVICE_PORT='8080'
MONITOR_LOG_URL='http://192.168.1.233:8080'
```

#### 4.2.4 VAuth 国密配置

```bash
# UKey 配置
VAUTH_MOCK_MODE='false'                    # 生产环境必须为 false
VAUTH_DEVICE_TYPE='ukey'                   # 设备类型：ukey 或 sdf
VAUTH_PASSWORD='88888888'                   # UKey PIN 码
VAUTH_AUTH_ID='44030000003330000305'        # 发布网关认证 ID
VAUTH_SERVER_ID='44010100003330003024'      # 管控平台认证 ID

# UKey 绑定（同机双 UKey 部署时必须配置）
VAUTH_UKEY_PATH='770/SKF_APP/ECC_Container_CA'
VAUTH_UKEY_SN=''                           # UKey 序列号
VAUTH_UKEY_CER_SN=''                       # 证书序列号
VAUTH_UKEY_CER_ID=''                       # 证书 ID
```

**注意**：`VAUTH_AUTH_ID` 和 `VAUTH_SERVER_ID` 必须与管控平台配置一致。

#### 4.2.5 网络配置

```bash
# 本机 IP 地址（用于 JmDNS 服务发现）
PROVIDER_JMDNS_BIND_ADDRESS='192.168.1.25'
PROVIDER_JMDNS_ADVERTISE_HOST='192.168.1.25'
```

### 4.3 可选配置项

#### 4.3.1 MinIO 对象存储（可选）

```bash
MINIO_ENABLED=true
MINIO_HOST='192.168.1.31'
MINIO_PORT='9000'
MINIO_ACCESS_KEY='admin'
MINIO_SECRET_KEY='your_minio_secret'
```

#### 4.3.2 MQTT Agent（公网部署时配置）

```bash
MQTT_PASSWORD=your_mqtt_password

MQTT_TENANT_ID=default
MQTT_SITE_ID=site-001
```

```bash
SECURE_PUBLISH_ENABLED='true'
SECURE_PUBLISH_TRUST_STORE_DIR='/opt/publish-gateway/trust'
SECURE_PUBLISH_TRUSTED_KEY_IDS=''
SECURE_PUBLISH_DEFAULT_KEY_ID='default'
```

## 5. 执行部署

### 5.1 预检查（推荐）

```bash
bash stage2/install.sh --check
```

预检查会依次执行：
- 加载配置
- 校验参数
- 检查硬件资源
- 检查 Docker 环境
- 检测端口冲突
- 检查交付文件
- 生成 .env
- 验证 Compose

如果有报错，根据提示修复问题后重新执行。

### 5.2 正式部署

```bash
bash stage2/install.sh
```

安装器会自动完成以下步骤：

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 加载配置 | 读取 deploy.conf |
| 2 | 自动生成密码 | 将占位符替换为强密码 |
| 3 | 校验配置 | 检查所有参数合法性 |
| 4 | 检查硬件 | 验证 CPU/内存/磁盘 |
| 5 | 检查 Docker | 确认 Docker 可用 |
| 6 | 检测端口冲突 | 发现冲突会提示 |
| 7 | 检查交付文件 | 确认所有文件完整 |
| 8 | 生成环境变量 | 写入 .env 文件 |
| 9 | 验证 Compose | 确认 docker-compose.yml 合法 |
| 10 | 配置防火墙 | 自动开放必需端口 |
| 11 | 准备运行目录 | 创建数据/日志目录 |
| 12 | 启动服务 | 启动 Redis 和加密网关 |
| 13 | 健康检查 | 等待服务就绪 |
| 14 | 生成账户文件 | 输出 account.txt |

### 5.3 部署成功标志

部署成功后会看到以下输出：

```
[SUCCESS] publish-gateway 部署完成！
```

同时会在部署目录下生成：
- `account.txt` — 包含所有访问地址、密码、常用命令
- `.env` — 环境变量文件

## 8. 常见问题排查

### 8.1 部署失败常见原因

#### 问题：端口被占用

**症状**：安装器提示 "端口 XXXX 已被占用"

**解决**：
```bash
# 查看占用端口的进程
ss -ltnp | grep <端口号>

# 或者修改 deploy.conf 中对应的端口号
vi deploy.conf
```

#### 问题：Docker 镜像缺失

**症状**：安装器提示 "缺少 Docker 镜像"

**解决**：
```bash
# 手动导入镜像
docker load -i images/publish-gateway.tar

# 或者允许从网络拉取（需联网）
# deploy.conf 中设置：
PULL_PUBLIC_IMAGES=true
```

#### 问题：容器启动失败

**症状**：容器状态显示 Exited 或 Restarting

**解决**：
```bash
# 查看容器日志找出原因
docker logs gateway-udp-proxy

# 常见原因：
# - MySQL 连接失败：检查 DB_HOST、DB_PORT、DB_PASSWORD
# - UKey 未识别：检查 USB 设备是否正确挂载
# - 证书缺失：检查 certs/ 目录
```

#### 问题：UKey 未识别

**症状**：日志显示 "UKey device not found"

**解决**：
```bash
# 1. 检查 UKey 是否插入
lsusb | grep -i ukey

# 2. 检查 USB 设备挂载
docker exec gateway-udp-proxy ls -la /dev/bus/usb/

# 3. 检查容器是否以 privileged 模式运行
docker inspect gateway-udp-proxy | grep -i privileged
```

#### 问题：数据库连接失败

**症状**：日志显示 "Connection refused" 或 "Access denied"

**解决**：
```bash
# 1. 检查 MySQL 是否运行
systemctl status mysql

# 2. 检查数据库是否存在
mysql -h 192.168.1.31 -u root -p -e "SHOW DATABASES LIKE 'udp_proxy_gateway';"

# 3. 检查用户权限
mysql -h 192.168.1.31 -u root -p -e "SELECT user, host FROM mysql.user;"
```

#### 问题：管控平台连接失败

**症状**：日志显示 "Connection refused to monitor-host"

**解决**：
```bash
# 1. 检查管控平台是否运行
curl http://192.168.1.233:8080/actuator/health

# 2. 检查网络连通性
ping 192.168.1.233

# 3. 检查防火墙
telnet 192.168.1.233 8080
```

### 8.2 服务器重启后

服务器重启后，Docker 容器会自动启动（配置了 `restart: always`）。如果服务未自动恢复：

```bash
# 手动启动所有服务
cd /opt/publish-gateway
docker-compose up -d

# 等待 30 秒后检查状态
docker ps | grep gateway-udp-proxy
```

### 8.3 日志文件位置

| 日志类型 | 位置 |
|---------|------|
| 容器日志 | `/opt/publish-gateway/logs/` |
| 应用日志 | 容器内 `/app/logs/` |
| Docker 日志 | `docker logs gateway-udp-proxy` |

## 9. 升级与回滚

### 9.1 升级流程

```bash
# 1. 停止当前服务
docker stop gateway-udp-proxy

# 2. 备份当前镜像
docker tag gateway-udp-proxy:1.0.0 gateway-udp-proxy:backup

# 3. 加载新镜像
docker load -i images/publish-gateway-new.tar

# 4. 启动新版本
docker-compose up -d

# 5. 验证健康状态
curl http://127.0.0.1:8092/actuator/health
```

### 9.2 回滚

如果新版本有问题，可以回滚到旧版本：

```bash
# 1. 停止当前服务
docker stop gateway-udp-proxy

# 2. 恢复旧镜像
docker tag gateway-udp-proxy:backup gateway-udp-proxy:1.0.0

# 3. 启动旧版本
docker-compose up -d

# 4. 验证健康状态
curl http://127.0.0.1:8092/actuator/health
```

### 9.3 数据库备份

```bash
# 备份数据库
mysqldump -h 192.168.1.31 -u root -p udp_proxy_gateway > backup_$(date +%Y%m%d).sql

# 恢复数据库
mysql -h 192.168.1.31 -u root -p udp_proxy_gateway < backup_20260626.sql
```

## 10. 安全建议

### 10.1 密码安全

- 使用强密码（至少 8 位，包含大小写字母、数字、特殊字符）
- 定期更换密码
- 妥善保管 `account.txt` 文件

### 10.2 网络安全

- 仅开放必需的端口
- 使用防火墙限制访问来源
- 生产环境建议使用 HTTPS

### 10.3 UKey 安全

- UKey 设备应妥善保管
- 不要将 UKey PIN 码泄露给他人
- 定期检查 UKey 设备状态

### 10.4 日志安全

- 定期清理日志文件
- 日志中可能包含敏感信息，注意保护
