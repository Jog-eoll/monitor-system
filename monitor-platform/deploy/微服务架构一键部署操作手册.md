# 微服务架构一键部署操作手册

本文档用于指导部署人员在单台 Linux 服务器上交付微服务架构的平台服务。脚本入口位于 `deploy/install.sh`，部署内容包括 MySQL、Redis、Nacos、MinIO、EMQX（MQTT 消息代理）、平台微服务、Nginx 前端静态资源。

> 说明：本脚本部署的是平台微服务栈。加密网关 `gateway-udp-proxy` 如仍采用融合离线包方案，请继续使用加密网关独立交付包部署。

> MQTT 说明：平台通过 MQTT 协议与公网部署的发布网关进行通信。EMQX 5 作为 MQTT 消息代理运行在平台侧，发布网关作为 MQTT Agent 连接 EMQX 接收下发指令并上报心跳和回复。当部署场景为平台在公网、设备在局域网时，必须启用 MQTT 通信模式。

## 1. 服务器要求

- 操作系统：Linux x86_64
- 用户权限：root 或可执行 Docker、开放端口的 sudo 用户
- CPU：建议 4 核及以上
- 内存：建议 8 GB 及以上
- 磁盘：建议 50 GB 及以上
- 软件：Docker、Docker Compose v2

如果现场允许脚本安装 Docker，可在执行部署时增加 `--auto-install-docker`。如果现场 Docker 已安装，不需要增加该参数。

## 2. 交付目录要求

将部署包放到服务器，例如：

```bash
/opt/monitor-platform/deploy
```

目录内至少需要包含：

```text
deploy/
├── install.sh
├── docker-compose.yml
├── stage2/
├── deploy.conf
├── mysql/
│   └── init/
│       ├── 00-create-app-user.sh
│       ├── monitor_platform_init.sql
│       ├── 02-info-publish-client.sql
│       └── nacos.sql
├── nacos/
│   └── conf/application.properties
├── emqx/
│   └── etc/
│       ├── emqx.conf
│       └── acl.conf
├── nginx/
│   ├── conf/nginx.conf
│   └── www/index.html
├── sdk/
│   └── lib/
├── images/
└── tar/
```

`images/` 和 `tar/` 用于存放 Docker 镜像离线包，二者任选其一即可。

## 3. 必须提供的镜像

私有业务镜像必须提供：

```text
monitor-platform-device:latest

monitor-platform-alarm:latest
monitor-platform-rule:latest
monitor-platform-content:latest
monitor-platform-forward:latest
monitor-platform-role:latest

monitor-platform-websocket:latest

```

公共基础镜像需要满足以下二选一：

- 服务器可以访问公网或内网镜像仓库，并在 `deploy.conf` 中配置 `PULL_PUBLIC_IMAGES=true`
- 或者离线包中同时提供以下镜像：

```text
nacos/nacos-server:v2.2.0
emqx/emqx:5.4.0
mysql:5.7
redis:latest

```

镜像包可放在：

```bash
/opt/monitor-platform/deploy/images
/opt/monitor-platform/deploy/tar
```

支持 `.tar`、`.tar.gz`、`.tgz`。版本更新时也可以直接传入完整一键部署包 `.tar.gz` 或解压后的包目录，脚本会自动查找其中的 `package/images/` 镜像归档。

## 4. UKey 和 SDK 文件

微服务中的 `monitor-ukey` 服务启动时会加载厂商 SDK，因此 SDK 文件必须随部署包一起提供。`UKEY_SETUP_MODE=deferred` 只表示现场物理 UKey、PIN、AuthId 可以后续配置，不表示 SDK 可以缺失。

如果现场暂时没有物理 UKey，配置：

```bash
UKEY_SETUP_MODE=deferred
```

该模式下平台基础服务可以先部署，UKey 认证能力后续再补充配置。

如果现场已经具备 UKey 并要求正式启用，配置：

```bash
UKEY_SETUP_MODE=required
VAUTH_SERVER_MODE=ukey
VAUTH_SERVER_PASSWORD=88888888
VAUTH_SERVER_AUTH_ID=实际认证ID
```

并将厂商 SDK 放入：

```bash
/opt/monitor-platform/deploy/sdk/lib
```

至少必须包含：

```text
libvauthsdk.so
```

如 SDK 依赖其他 `.so` 或授权文件，也必须一并放入 `sdk/lib/`。

## 5. MQTT 通信模块（EMQX）

### 5.1 概述

平台支持通过 MQTT 协议与远程发布网关通信，适用于平台部署在公网、设备部署在局域网的场景。EMQX 5 作为 MQTT 消息代理运行在平台侧（docker-compose 内），发布网关作为 MQTT Agent 主动连接 EMQX 建立长连接。

通信架构：

```text
平台（公网）                          发布网关（局域网）
┌──────────────────┐               ┌──────────────────┐
│ monitor-forward  │               │ gateway-udp-proxy│
│ (MQTT Publisher) │── EMQX ──────│ (MQTT Agent)     │
│                  │   Broker      │                  │
│ 订阅: /+/+/+/up/#│               │ 订阅: /.../down/#│
│ 发布: /.../down/ │               │ 发布: /.../up/   │
└──────────────────┘               └──────────────────┘
```

### 5.2 下发模式（DISPATCH_MODE）

平台通过 `DISPATCH_MODE` 配置项控制下发通道：

```text
mqtt（默认）标准 MQTT 主链路，适用于平台在公网、设备在局域网
http          运维人工降级通道，适用于 Broker 或网关 Agent 故障隔离
```

建议上线策略：标准部署保持 `DISPATCH_MODE=mqtt`；如需降级，由运维手工切换为 `DISPATCH_MODE=http`，故障恢复后再切回 `mqtt`。

### 5.3 EMQX 部署

EMQX 以 Docker 容器方式运行，已在 `docker-compose.yml` 中定义。默认端口：

```text
1883   MQTT TCP 明文（容器内部使用）
8883   MQTT TLS 加密（发布网关连接）
18083  EMQX Dashboard（管理后台，可选开放）
```

EMQX 容器启动后会自动初始化。如果现场需要自定义 ACL 规则或 TLS 证书，将配置文件放入：

```bash
/opt/monitor-platform/deploy/emqx/etc/
```

### 5.4 MQTT Topic 规范

```text
/{tenantId}/{siteId}/{deviceId}/down/proxy-command    平台下发指令
/{tenantId}/{siteId}/{deviceId}/up/reply              网关上报回复
/{tenantId}/{siteId}/{deviceId}/up/heartbeat          网关上报心跳
```

平台订阅 `/+/+/+/up/#`（所有上行消息），发布到 `/{tenantId}/{siteId}/{deviceId}/down/proxy-command`。

### 5.5 发布网关 MQTT Agent 配置

发布网关（`gateway-udp-proxy`）作为 MQTT 客户端连接 EMQX，在融合离线包的 `application.yml` 中通过 `mqtt-agent` 配置段控制：

```bash
# 是否启用 MQTT Agent（标准主链路默认 true；HTTP 人工降级时才设为 false）
MQTT_AGENT_ENABLED=true

# EMQX 连接地址
MQTT_BROKER_URL=ssl://公网EMQX地址:8883

# EMQX 认证（如启用认证则填写）
MQTT_USERNAME=
MQTT_PASSWORD=

# 网关在 MQTT 体系中的身份
MQTT_CLIENT_ID=publish-gateway-001
MQTT_TENANT_ID=default
MQTT_SITE_ID=site-001

# 指令去重 TTL（毫秒），防止 QoS 1 重复投递
MQTT_COMMAND_DEDUP_TTL_MS=86400000

# 断线重连间隔（毫秒）
MQTT_RECONNECT_INTERVAL_MS=30000
```

### 5.6 平台侧 MQTT 配置

平台 `monitor-forward` 模块的 MQTT 配置位于 Nacos 中的 `bootstrap.yml`（或环境变量）：

```bash
# 下发模式
DISPATCH_MODE=mqtt

# EMQX Broker 地址
MQTT_BROKER_URL=ssl://127.0.0.1:8883

# EMQX 认证
MQTT_USERNAME=
MQTT_PASSWORD=

# 平台 MQTT 身份
MQTT_TENANT_ID=default
MQTT_SITE_ID=site-001
MQTT_PLATFORM_CLIENT_ID=monitor-platform-001
```

### 5.7 指令下发与幂等

平台通过 MQTT 下发 `PROXY_COMMAND` 消息时，会自动在 `device_mqtt_command` 表中记录指令状态。网关侧通过 `messageId` 实现幂等去重，防止 QoS 1 场景下的重复执行。

网关收到指令后根据 Action 的 `mode` 字段决定处理方式：

```text
SELF_APPLY  网关自身处理（如应用链路配置）
HTTP        网关通过局域网 HTTP 转发给目标设备（终端网关/情报板）
```

### 5.8 心跳机制

发布网关启动后每 30 秒上报一次心跳消息（`HEARTBEAT`），包含网关设备 ID、状态和时间戳。平台侧收到心跳后更新设备在线状态，超过阈值未收到心跳则标记为离线。

## 6. 生成并填写配置文件

进入部署目录：

```bash
cd /opt/monitor-platform/deploy
```

首次部署生成配置文件：

```bash
bash install.sh --init-config
```

编辑配置：

```bash
vi deploy.conf
```

重点修改以下配置：

```bash
MYSQL_PASSWORD=替换为现场密码
MYSQL_ROOT_PASSWORD=替换为现场root密码
REDIS_PASSWORD=替换为现场密码
MINIO_ROOT_PASSWORD=替换为现场密码
MINIO_SECRET_KEY=替换为现场密码
UKEY_ADMIN_PASSWORD=替换为平台UKey管理员密码
UKEY_PASSWORD_ENCRYPT_KEY=替换为生产UKey密码加密密钥
UKEY_SETUP_MODE=deferred
EMQX_DASHBOARD_PASSWORD=替换为EMQX管理后台密码

# ---- MQTT 下发配置（详见第 5 节）----
# 下发模式：mqtt（标准主链路）/ http（运维人工降级）
DISPATCH_MODE=mqtt
# EMQX Broker 地址，发布网关和平台共用此地址
MQTT_BROKER_URL=ssl://公网EMQX地址:8883
# EMQX 认证（如 EMQX 启用认证则填写）
MQTT_USERNAME=
MQTT_PASSWORD=
# 平台侧 MQTT 身份标识
MQTT_TENANT_ID=default
MQTT_SITE_ID=site-001
MQTT_PLATFORM_CLIENT_ID=monitor-platform-001
MQTT_AUTH_ENABLED=true
MQTT_DEVICE_DEFAULT_PASSWORD=替换为网关共享设备密码
MQTT_ALLOW_EMPTY_DEVICE_PASSWORD=false
MQTT_PLATFORM_CLIENT_PREFIX=monitor-platform,platform,server
```

单机部署时以下容器内部地址不要修改：

```bash
MYSQL_HOST=db
MYSQL_PORT=3306
REDIS_HOST=redis
REDIS_PORT=6379
NACOS_HOST=nacos
NACOS_PORT=8848
MINIO_ENDPOINT=http://minio:9000
```

如果服务器端口冲突，可以修改宿主机端口，例如：

```bash
MYSQL_HOST_PORT=23306
REDIS_HOST_PORT=26379
NACOS_HOST_PORT=18848
MINIO_API_PORT=19000
NGINX_PORT=80
# EMQX 端口（MQTT 通信）
EMQX_MQTT_PORT=1883
EMQX_MQTTS_PORT=8883
EMQX_DASHBOARD_PORT=18083
```

## 9. 正式部署

执行：

```bash
bash install.sh
```

如果允许脚本自动安装 Docker：

```bash
bash install.sh --auto-install-docker
```

如果不希望脚本自动开放防火墙端口：

```bash
bash install.sh --no-auto-firewall
```

部署成功后脚本会自动检查：

- MySQL、Redis、Nacos、MinIO 是否可用
- EMQX 是否可访问（`http://127.0.0.1:18083/api/v5/status`）
- MinIO 初始化容器是否成功退出
- 各微服务 `/actuator/health` 是否可访问
- 各微服务是否注册到 Nacos
- 当 `DISPATCH_MODE=mqtt` 时，检查 EMQX 1883/8883 端口是否监听
- 部署报告是否生成

### 9.1 版本镜像更新

首版部署成功后，后续版本可以只传入新镜像包并执行更新：

```bash
# 推荐：使用首次部署后生成的管理脚本
bash ctl.sh update-images /tmp/monitor-platform-v1.1.0.tar.gz

# 也可以直接调用 stage2 入口
bash install.sh --update-images /tmp/images --yes
```

`--update-images` 支持三种输入：

- 单个 `docker save` 生成的镜像归档。
- 包含多个 `.tar`、`.tar.gz`、`.tgz` 镜像归档的目录。
- 完整一键部署包 `.tar.gz` 或解压目录，脚本会读取其中的 `package/images/`。

更新流程会先记录当前私有业务镜像 ID 到 `backups/image-updates/时间/image-ids-before.txt`，加载新镜像后对比 `monitor-platform-*` 镜像 ID，只对发生变化的 `monitor-*` 服务执行 `docker compose up -d --no-deps --force-recreate`，随后复用 `/actuator/health` 和 Nacos 注册检查。

该流程只更新平台业务镜像，不自动更新 MySQL、Redis、Nacos、MinIO、Nginx、EMQX 等基础组件镜像，也不会自动执行数据库 schema 变更。版本包含 SQL/Liquibase 变更时，必须先按版本交付说明完成数据库变更，再执行镜像更新。

## 11. 常见问题

### 11.1 提示缺少私有镜像

原因：业务镜像没有提前加载，也没有放入 `images/` 或 `tar/`。

处理：

```bash
cp *.tar /opt/monitor-platform/deploy/images/
bash install.sh --check
```

### 11.2 提示缺少 `nginx/www/index.html`

原因：前端静态文件没有放入部署包。

处理：将前端打包后的静态文件放入：

```bash
/opt/monitor-platform/deploy/nginx/www
```

### 11.3 提示缺少 `sdk/lib/libvauthsdk.so`

原因：UKey 服务启动时必须加载厂商 SDK，缺少该文件会导致服务启动失败。

处理：将 SDK 文件补到：

```bash
/opt/monitor-platform/deploy/sdk/lib
```

如果现场没有物理 UKey，仍然需要保留 SDK 文件，同时将配置设为：

```bash
UKEY_SETUP_MODE=deferred
```

### 11.4 端口被占用

先查看占用：

```bash
ss -lntp
```

然后修改 `deploy.conf` 中对应的宿主机端口，例如 `NGINX_PORT`、`MYSQL_HOST_PORT`、`NACOS_HOST_PORT`。

### 11.5 服务启动失败

查看容器日志：

```bash
docker logs --tail=200 monitor-ukey
docker logs --tail=200 monitor-platform-gateway
docker logs --tail=200 monitor-content
```

重新生成报告：

```bash
bash install.sh --report
```

### 11.6 EMQX 容器启动失败

原因：EMQX 容器依赖 MySQL 健康检查，如果 MySQL 尚未就绪，EMQX 可能启动失败。也可能是 1883/8883/18083 端口被占用。

处理：

```bash
# 查看 EMQX 日志
docker logs --tail=200 emqx
# 检查端口占用
ss -lntp | grep -E '1883|8883|18083'
# 重启 EMQX
docker compose restart emqx
```

### 11.7 发布网关无法连接 EMQX

原因：发布网关（`gateway-udp-proxy`）的 `MQTT_AGENT_ENABLED` 未设为 `true`，或 `MQTT_BROKER_URL` 地址不正确，或网络不通。

处理：

1. 确认发布网关 `application.yml` 中 `mqtt-agent.enabled` 为 `true`
2. 确认 `MQTT_BROKER_URL` 指向平台侧 EMQX 的公网可达地址
3. 确认平台服务器防火墙已开放 8883 端口
4. 查看发布网关日志中 MQTT 连接错误信息：

```bash
# 在发布网关服务器上
grep -i "mqtt" /opt/publish-gateway/logs/gateway-udp-proxy.log | tail -50
```

### 11.8 MQTT 模式下指令下发无响应

原因：`DISPATCH_MODE` 配置不正确，或平台与网关的 `tenantId`/`siteId` 不一致。

处理：

1. 确认平台侧 `DISPATCH_MODE=mqtt`
2. 确认平台侧和网关侧的 `MQTT_TENANT_ID` 和 `MQTT_SITE_ID` 一致
3. 在 EMQX Dashboard（`http://平台IP:18083`）中检查客户端连接状态
4. 查看平台 `monitor-forward` 日志中的 MQTT 发布记录：

```bash
docker logs --tail=200 monitor-forward 2>&1 | grep -i "mqtt"
```

## 12. 回滚方式

停止服务：

```bash
docker compose -f docker-compose.yml down
```

如需保留数据库和文件数据，不要删除 `mysql/data`、`minio/data1`、`minio/data2`。

如需完全清理测试环境，确认无生产数据后再删除数据目录。
