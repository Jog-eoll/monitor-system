# 单体架构通用部署文档

## 1. 文档范围

本文档用于在 Linux 服务器上部署单体版监控平台，并可按现场环境迁移到不同服务器。

| 服务 | 默认部署目录 | 容器名 | 默认镜像 | 默认端口 | 是否必需 |
| --- | --- | --- | --- | --- | --- |
| 监控平台单体应用 | `/opt/monitor-platform-monolith` | `monitor-platform-monolith` | `monitor-platform-monolith:1.0.0` | `8080/tcp` | 是 |
| 发布 UDP 网关 | `/opt/publish-gateway` | `gateway-udp-proxy` | `gateway-udp-proxy:1.0.0` | `8092/tcp`, `18092/udp`, `5353/udp` | 按业务需要 |
| Nginx 入口 | `/opt/monitor-platform/nginx` | `monitor-nginx` | `nginx:alpine` | `80/tcp` | 推荐 |

说明：

- `monitor-platform-monolith` 是监控平台单体应用，合并原微服务部署中的多个平台能力。
- `gateway-udp-proxy` 用于发布链路、UKey、mDNS 注册和客户端 UDP 中继；如果现场不部署发布链路，可不部署该服务。
- MySQL、Redis、MinIO 可以与应用同机部署，也可以部署在独立基础组件服务器上。
- 密码、Secret、AccessKey、JWT 等敏感字段必须由现场填写，本文档不记录明文。

## 2. 变量约定

后续命令和配置统一使用以下占位符：

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `<APP_HOST>` | 单体应用部署服务器 IP 或域名 | `192.168.1.233` |
| `<BASE_HOST>` | MySQL、Redis、MinIO 所在服务器 IP 或域名 | `192.168.1.31` |
| `<MYSQL_PASSWORD>` | MySQL 密码 | 现场填写 |
| `<REDIS_PASSWORD>` | Redis 密码 | 现场填写 |
| `<MINIO_ACCESS_KEY>` | MinIO AccessKey | 现场填写 |
| `<MINIO_SECRET_KEY>` | MinIO SecretKey | 现场填写 |
| `<JWT_SECRET>` | JWT 强随机密钥 | 现场填写 |
| `<UKEY_PASSWORD>` | UKey 密码 | 现场填写 |

参考环境：

| 项目 | 推荐/已验证值 |
| --- | --- |
| 操作系统 | CentOS 7 或其他支持 Docker 的 Linux |
| Docker | 20.x 及以上 |
| Docker Compose | `docker-compose` 1.29.x 或 Docker Compose v2 |
| Java 运行环境 | 镜像内置 OpenJDK 8 JRE |
| 时区 | `Asia/Shanghai` |

## 3. 部署拓扑

### 3.1 推荐拓扑

```text
用户 / 前端
   |
   | http://<APP_HOST>:80
   v
monitor-nginx
   |
   | proxy_pass http://<APP_HOST>:8080
   v
monitor-platform-monolith
   |-- MySQL  -> <BASE_HOST>:3306 / monitor_platform
   |-- Redis  -> <BASE_HOST>:6379 / db 0
   |-- MinIO  -> http://<BASE_HOST>:9000 / monitor-content
   |-- UKey   -> /dev/bus/usb + /opt/monitor-platform-monolith/lib
   |
   | device registry / heartbeat
   v
gateway-udp-proxy
   |-- MySQL  -> <BASE_HOST>:3306 / udp_proxy_gateway
   |-- Redis  -> <BASE_HOST>:6379 / db 2
   |-- MinIO  -> <BASE_HOST>:9000 / monitor-content
   |-- UKey   -> /dev/bus/usb + /opt/publish-gateway/lib
   |-- mDNS   -> <APP_HOST>:5353/udp
   |-- relay  -> <APP_HOST>:18092/udp
```

### 3.2 同机基础组件拓扑

如果 MySQL、Redis、MinIO 与应用部署在同一台服务器：

- `<APP_HOST>` 和 `<BASE_HOST>` 可填写同一个 IP。
- 如果容器使用 `network_mode: host`，应用访问宿主机服务时可使用 `127.0.0.1` 或服务器内网 IP。
- 推荐优先使用服务器内网 IP，便于后续迁移到独立基础组件服务器。

## 4. 前置条件

### 4.1 服务器软件

| 软件 | 要求 | 验证命令 |
| --- | --- | --- |
| Docker | 已安装并启动 | `docker --version && systemctl status docker` |
| Docker Compose | 1.x 或 v2 可用 | `docker-compose --version` 或 `docker compose version` |

| 组件 | 默认端口 | 用途 | 验证方式 |
| --- | --- | --- | --- |
| MySQL | `3306` | 单体平台库、发布网关库 | `mysql -h<BASE_HOST> -P3306 -u账号 -p` |
| Redis | `6379` | 缓存、会话、发布网关缓存 | `redis-cli -h <BASE_HOST> -p 6379 -a 密码 ping` |
| MinIO | `9000` | 内容文件、预审核文件、发布文件 | 登录 MinIO 控制台或使用客户端检查 bucket |

数据库要求：

| 数据库 | 使用方 | 初始化方式 |
| --- | --- | --- |
| `monitor_platform` | `monitor-platform-monolith` | 应用启动时通过 Liquibase 创建/更新表结构 |
| `udp_proxy_gateway` | `gateway-udp-proxy` | 需要提前创建库并导入发布网关表结构 |

### 6.2 UKey / VAuth

| 变量 | 示例 | 必填 | 说明 |
| --- | --- | --- | --- |
| `VAUTH_SERVER_MODE` | `ukey` | 是 | VAuth 模式，真实硬件使用 `ukey` |
| `VAUTH_SERVER_REQUIRED` | `true` | 是 | 是否强制启用 VAuth |
| `VAUTH_SERVER_PASSWORD` | `<UKEY_PASSWORD>` | 是 | 服务端 UKey 密码 |
| `VAUTH_SERVER_AUTH_ID` | `<SERVER_AUTH_ID>` | 否 | 服务端认证 ID；不填时单 UKey 场景会自动从 `cerId` 推导 |
| `VAUTH_SERVER_LIBRARY_PATH` | `/opt/monitor-platform-monolith/lib` | 是 | SDK 动态库路径 |
| `VAUTH_SERVER_DEPENDENCY_PATHS` | `/opt/monitor-platform-monolith/lib` | 是 | SDK 依赖库路径 |
| `VAUTH_SERVER_UKEY_PATH` | `<SERVER_UKEY_PATH>` | 否 | 多 UKey 场景绑定服务端 UKey 容器路径，来自 SDK 枚举结果 |
| `VAUTH_SERVER_UKEY_SN` | `<SERVER_UKEY_SN>` | 否 | 多 UKey 场景绑定服务端 UKey SN，来自 SDK 枚举结果 |
| `VAUTH_SERVER_UKEY_CER_SN` | `<SERVER_UKEY_CER_SN>` | 否 | 多 UKey 场景绑定服务端证书序列号，来自 SDK 枚举结果 |
| `VAUTH_SERVER_UKEY_CER_ID` | `<SERVER_UKEY_CER_ID>` | 否 | 多 UKey 场景绑定服务端证书 ID，来自 SDK 枚举结果 |

说明：

- `monitor-platform-monolith` 启动时会调用 `VAuth_ListUkeyInfos` 枚举 UKey。
- 如果配置了 `VAUTH_SERVER_AUTH_ID`，服务端会按 `cerId == authId` 或 `cerId` 以 `authId_` 开头匹配 UKey。
- 如果未配置 `VAUTH_SERVER_AUTH_ID` 且只发现一个 UKey，服务端会从该 UKey 的 `cerId` 自动推导认证 ID。
- 如果同机存在多个 UKey，必须配置 `VAUTH_SERVER_AUTH_ID` 或至少一个 `VAUTH_SERVER_UKEY_*` 绑定条件，否则服务端拒绝默认选择设备。
- 发布网关 `VAUTH_UKEY_*` 字段也支持读取和匹配，可用于绑定发布网关 UKey。

### 6.3 账号、JWT 和 JVM

| 变量 | 示例 | 必填 | 说明 |
| --- | --- | --- | --- |
| `UKEY_ADMIN_USERNAME` | `admin` | 是 | UKey 管理账号 |
| `UKEY_ADMIN_PASSWORD` | `<CHANGE_ME>` | 是 | UKey 管理密码 |
| `JWT_SECRET` | `<JWT_SECRET>` | 是 | JWT 签名密钥，建议使用强随机字符串 |
| `JWT_EXPIRE_HOURS` | `8` | 是 | JWT 过期时间，单位小时 |
| `JAVA_OPTS` | `-Xms512m -Xmx1024m` | 是 | JVM 参数 |
| `ALARM_AUTO_BLACK_SCREEN_ENABLED` | `true` | 否 | 自动黑屏告警开关，未配置时默认 `true` |
| `UKEY_PASSWORD_ENCRYPT_KEY` | `<CHANGE_ME>` | 否 | UKey 密码加密密钥，未配置时使用应用默认值 |

## 8. 构建与交付

### 8.1 编译单体应用

在项目根目录执行：

```bash
cd /path/to/monitor-platform
mvn -pl monitor-platform-monolith -am -DskipTests clean package
```

生成文件：

```text
monitor-platform-monolith/target/monitor-platform-monolith-1.0.0.jar
```

### 8.2 构建镜像

推荐方式：在可访问 Docker 的机器上构建镜像。

```bash
cd /path/to/monitor-platform
docker build -t monitor-platform-monolith:1.0.0 ./monitor-platform-monolith
```

如果需要通过 Maven 触发 Docker 插件构建，必须先确认父 POM 中 `dockerHost` 指向正确的目标 Docker 地址。不要直接沿用测试环境 IP。

### 8.3 离线镜像交付

适用于无法访问镜像仓库或远程 Docker API 的环境。

```bash
docker save monitor-platform-monolith:1.0.0 -o monitor-platform-monolith_1.0.0.tar
scp monitor-platform-monolith_1.0.0.tar root@<APP_HOST>:/opt/monitor-platform-monolith/
ssh root@<APP_HOST>
cd /opt/monitor-platform-monolith
docker load -i monitor-platform-monolith_1.0.0.tar
docker images | grep monitor-platform-monolith
```

发布网关镜像同理：

```bash
docker save gateway-udp-proxy:1.0.0 -o gateway-udp-proxy_1.0.0.tar
scp gateway-udp-proxy_1.0.0.tar root@<APP_HOST>:/opt/publish-gateway/
ssh root@<APP_HOST>
cd /opt/publish-gateway
docker load -i gateway-udp-proxy_1.0.0.tar
docker images | grep gateway-udp-proxy
```

### 9.6 配置 Nginx

Nginx upstream 应指向单体应用：

```nginx
upstream monitor-monolith {
    server <APP_HOST>:8080;
}

server {
    listen 80;
    server_name _;
    client_max_body_size 100M;

    location / {
        proxy_pass http://monitor-monolith;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /notification {
        proxy_pass http://monitor-monolith/notification;
        proxy_http_version 1.1;
        proxy_read_timeout 3600s;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    location /ws-endpoint {
        proxy_pass http://monitor-monolith/ws-endpoint;
        proxy_http_version 1.1;
        proxy_read_timeout 3600s;
        proxy_buffering off;
        proxy_cache off;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }

    location /health {
        return 200 'OK';
        add_header Content-Type text/plain;
    }
}
```

重载 Nginx：


## 14. 常见问题排查

| 现象 | 高概率原因 | 排查步骤 | 修复方案 |
| --- | --- | --- | --- |
| 单体应用健康检查不是 `UP` | MySQL、Redis 或 MinIO 连接失败 | `docker logs monitor-platform-monolith` 查看 `Communications link failure`、`Connection refused`、认证失败 | 修正 `.env` 中基础组件地址、端口、账号密码 |
| `UnsatisfiedLinkError` 或 SDK 初始化失败 | VAuth SDK 动态库缺失或路径错误 | 检查 `lib/` 是否包含 `libvauthsdk.so` 和依赖库，检查 `LD_LIBRARY_PATH` | 补齐 `/opt/monitor-platform-monolith/lib` 或 `/opt/publish-gateway/lib`，重启容器 |
| UKey 打开失败 | USB 未挂载、UKey 不存在、UKey SN/路径不匹配 | `lsusb`、`ls -lah /dev/bus/usb`、查看 VAuth 日志 | 确认 UKey 插入；修正 `VAUTH_*_UKEY_*` 变量 |
| 发布网关注册失败 | `MONITOR_HOST` 或端口错误，单体应用不可访问 | `curl http://<APP_HOST>:8080/actuator/health` | 修正 `MONITOR_HOST=<APP_HOST>`，端口统一为单体 `SERVER_PORT` |
| Nginx 访问异常 | Nginx upstream 指向错误或配置未重载 | `docker exec monitor-nginx nginx -T | grep -n monitor-monolith` | 将 upstream 指向 `<APP_HOST>:8080` 后 reload |
| 客户端 UDP 中继不可用 | `18092/udp` 未监听或防火墙未放行 | `ss -lunp | grep 18092` | 确认 `CLIENT_RELAY_ENABLED=true`，放行 UDP 18092 |
| mDNS 发现异常 | 绑定地址错误或 5353/udp 被占用 | `ss -lunp | grep 5353`，查看 `JmDNS-Provider` 日志 | 修正 `PROVIDER_JMDNS_BIND_ADDRESS=<APP_HOST>` |
| 数据表缺失 | 数据库未初始化或 Liquibase 未执行 | 查看应用启动日志、检查数据库表 | 单体库由 Liquibase 处理；发布网关库需导入对应 SQL |

## 15. 安全注意事项

1. 不要把 `.env` 明文密码提交到代码仓库。
2. 不建议开放无 TLS 的 Docker `2375/tcp`。如必须临时使用，应通过防火墙限制来源 IP。
3. 生产环境不建议使用弱 SSH 密码，应改为密钥登录并关闭密码登录。
4. `.env` 权限建议设置为 `600`：

```bash
chmod 600 /opt/monitor-platform-monolith/.env
chmod 600 /opt/publish-gateway/.env
```

5. `network_mode: host` 会直接占用宿主机端口，部署前必须确认端口不冲突。
6. UKey SDK 动态库和证书目录属于敏感交付物，应限制服务器读写权限。

## 16. 迁移到新环境 Checklist

部署到新服务器前必须确认：

- [ ] `<APP_HOST>` 已确定，且能被用户、发布网关、客户端访问。
- [ ] `<BASE_HOST>` 已确定，MySQL、Redis、MinIO 可从 `<APP_HOST>` 访问。
- [ ] `monitor_platform` 数据库已创建。
- [ ] 如果部署发布网关，`udp_proxy_gateway` 数据库已创建并导入表结构。
- [ ] `.env` 中所有 `<CHANGE_ME>`、`<BASE_HOST>`、`<APP_HOST>`、UKey 参数已替换。
- [ ] `/dev/bus/usb` 可访问，真实 UKey 已插入。
- [ ] SDK 动态库已放入 `lib/`，证书和验签公钥已放入对应目录。
- [ ] `80/tcp`、`8080/tcp`、`8092/tcp`、`18092/udp`、`5353/udp` 未冲突并按需放行。
- [ ] `docker-compose config` 或 `docker compose config` 校验通过。
- [ ] `curl http://<APP_HOST>:8080/actuator/health` 返回 `UP`。
