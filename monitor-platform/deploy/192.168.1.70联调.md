# 192.168.1.70 MQTT 联调说明

本文档用于指导内网网关 `192.168.77.25` / `192.168.77.26` 接入平台服务器 `192.168.1.70`，完成基于 MQTT 的注册、心跳、平台下发、设备回执联调。

## 1. 联调目标

当前网络用于模拟“平台不可直接访问网关，网关可主动访问平台”的场景：

```text
192.168.77.25 / 192.168.77.26
        |
        | 主动 MQTT 长连接
        v
192.168.1.70 平台 + EMQX
```

验收标准：

1. 网关能从 `192.168.77.0/24` 主动连接 `192.168.1.70:1883`。
2. 网关启动后主动上报注册信息，平台能保存设备编号、类型、内网 IP、端口、版本等信息。
3. 网关按 30 秒左右周期上报心跳，平台能刷新在线状态。
4. 平台通过 MQTT 下发命令，网关收到后执行，并通过 `up/reply` 回传结果。
5. 平台不能 ping 通或不能直接访问网关，不作为失败标准。

## 2. 平台侧现状

`192.168.1.70` 已部署微服务平台和 EMQX，当前联调参数如下：

| 项 | 值 |
| --- | --- |
| Web 入口 | `http://192.168.1.70/` |
| MQTT Broker | `tcp://192.168.1.70:1883` |
| MQTTS 预留端口 | `ssl://192.168.1.70:8883` |
| EMQX Dashboard | `http://192.168.1.70:18083/` |
| tenantId | `default` |
| siteId | `site-001` |
| 平台 MQTT clientId | `monitor-platform-001` |
| 平台下发模式 | `DISPATCH_MODE=mqtt` |

说明：

- 当前最小联调优先使用 `1883` 明文 MQTT。
- 后续启用 TLS / 账号认证 / ACL 时，网关侧只需要替换 broker、证书和账号配置，Topic 与消息结构不变。
- 不要把 MQTT 密码、证书私钥、UKey PIN 写入本文档或 Git 仓库。

## 3. 网关身份分配

MQTT 的 `clientId` 必须全局唯一。两台网关不能共用 `publish-gateway-001`，否则 EMQX 会出现互相踢下线。

推荐分配：

| 设备 | 推荐角色 | MQTT_CLIENT_ID | REGISTRY_CLIENT_ID | 注册 host | 注册 port |
| --- | --- | --- | --- | --- | ---: |
| `192.168.77.25` | 加密网关 / 发布网关 MQTT Agent | `publish-gateway-25` | `publish-gateway-25` | `192.168.77.25` | `8092` |
| `192.168.77.26` | 解密网关 / 内网目标设备 | 不强制启用 MQTT | 不强制启用 MQTT | `192.168.77.26` | `8093` |

推荐模式是由 `192.168.77.25` 作为 MQTT Agent 统一接入平台，`192.168.77.26` 作为内网目标设备被 `192.168.77.25` 通过 HTTP 或 UDP 转发访问。

如果 `192.168.77.26` 后续也部署 MQTT Agent，则必须单独分配唯一身份，例如：

```text
MQTT_CLIENT_ID=terminal-gateway-26
REGISTRY_CLIENT_ID=terminal-gateway-26
MQTT_REGISTER_HOST=192.168.77.26
MQTT_REGISTER_PORT=8093
```

## 4. 网关侧配置

在网关部署目录的 `.env` 中启用 MQTT Agent。历史部署路径可能是 `/tmp/publish-gateway-standalone/.env`、`/opt/publish-gateway/.env` 或一键安装包生成的实际目录，以现场为准。

`192.168.77.25` 建议配置：

```bash
MQTT_AGENT_ENABLED=true
MQTT_BROKER_URL=tcp://192.168.1.70:1883
MQTT_USERNAME=
MQTT_PASSWORD=

MQTT_CLIENT_ID=publish-gateway-25
REGISTRY_CLIENT_ID=publish-gateway-25
MQTT_TENANT_ID=default
MQTT_SITE_ID=site-001

MQTT_REGISTER_ENABLED=true
MQTT_REGISTER_ON_CONNECT=true
MQTT_REGISTER_INTERVAL_SEC=300
MQTT_REGISTER_SERVICE_NAME=publish-gateway
MQTT_REGISTER_HOST=192.168.77.25
MQTT_REGISTER_PORT=8092
MQTT_REGISTER_VERSION=v1.0.0
MQTT_REGISTER_MANUFACTURER=sjwg
MQTT_REGISTER_MODEL=publish-gateway
MQTT_REGISTER_REMARK=77.25 mqtt integration

MQTT_RECONNECT_INTERVAL_MS=30000
MQTT_COMMAND_DEDUP_TTL_MS=86400000

MONITOR_HOST=192.168.1.70
```

如果现场包里的 `application.yml` 没有 `MQTT_REGISTER_*` 这些注册字段，应优先更新网关镜像或安装包。源码中的完整配置位于：

```text
publish-gateway/gateway-udp-proxy/src/main/resources/application.yml
```

## 5. 网络预检查

在 `192.168.77.25` 和需要直连 MQTT 的 `192.168.77.26` 上执行：

```bash
ip addr
ip route

timeout 5 bash -c 'cat < /dev/null > /dev/tcp/192.168.1.70/1883' && echo MQTT_PORT_OK
curl -I --connect-timeout 5 http://192.168.1.70/
```

预期：

- `192.168.1.70:1883` 返回 `MQTT_PORT_OK`。
- `http://192.168.1.70/` 能返回 HTTP 响应。
- 平台访问不到 `192.168.77.25` 或 `192.168.77.26` 是正常现象。

## 6. MQTT Topic 约定

统一格式：

```text
/{tenantId}/{siteId}/{deviceId}/{direction}/{messageType}
```

当前联调使用：

| 方向 | Topic | 说明 |
| --- | --- | --- |
| 网关订阅 | `/default/site-001/{deviceId}/down/#` | 接收平台下发 |
| 平台下发 | `/default/site-001/{deviceId}/down/proxy-command` | 当前主要命令通道 |
| 网关上报注册 | `/default/site-001/{deviceId}/up/register` | 主动注册 |
| 网关上报心跳 | `/default/site-001/{deviceId}/up/heartbeat` | 在线状态 |
| 网关上报回执 | `/default/site-001/{deviceId}/up/reply` | 命令结果 |

`deviceId` 必须与网关的 `REGISTRY_CLIENT_ID` 保持一致。

## 7. 消息格式

推荐统一使用 `MqttEnvelope` 外层信封：

```json
{
  "messageId": "uuid-or-snowflake",
  "messageType": "REGISTER",
  "tenantId": "default",
  "siteId": "site-001",
  "deviceId": "publish-gateway-25",
  "deviceType": "publish_gateway",
  "timestamp": 1783000000000,
  "payload": "{\"instanceId\":\"publish-gateway-25\"}"
}
```

平台当前也兼容 `up/register`、`up/heartbeat`、`up/reply` Topic 上直接发送业务 JSON，但网关正式实现应使用 `MqttEnvelope`。

### 7.1 注册 payload

平台注册处理要求至少包含：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `instanceId` 或 `deviceId` | 是 | 设备唯一编号 |
| `host` | 是 | 设备内网 IP |
| `port` | 是 | 设备服务端口 |
| `serviceName` | 建议 | 服务名，发布网关用 `publish-gateway` |
| `deviceType` | 建议 | 设备类型，发布网关用 `publish_gateway` |
| `version` | 建议 | 当前版本 |
| `manufacturer` | 建议 | 厂商或项目标识 |
| `model` | 建议 | 型号 |

业务 payload 示例：

```json
{
  "serviceName": "publish-gateway",
  "instanceId": "publish-gateway-25",
  "deviceId": "publish-gateway-25",
  "deviceType": "publish_gateway",
  "host": "192.168.77.25",
  "port": 8092,
  "version": "v1.0.0",
  "manufacturer": "sjwg",
  "model": "publish-gateway",
  "remark": "77.25 mqtt integration",
  "timestamp": 1783000000000
}
```

### 7.2 心跳 payload

```json
{
  "deviceId": "publish-gateway-25",
  "deviceType": "publish_gateway",
  "status": "ONLINE",
  "timestamp": 1783000000000,
  "metadata": {
    "clientId": "publish-gateway-25",
    "innerIp": "192.168.77.25",
    "serverPort": 8092,
    "version": "v1.0.0"
  }
}
```

### 7.3 回执 payload

平台下发的 `messageId` 必须原样放入 `commandMessageId`：

```json
{
  "commandMessageId": "platform-message-id",
  "status": "SUCCESS",
  "message": "执行成功",
  "gatewayDeviceId": "publish-gateway-25",
  "timestamp": 1783000000000,
  "data": {}
}
```

`status` 可用值：

| 状态 | 含义 |
| --- | --- |
| `RECEIVED` | 网关已收到 |
| `PROCESSING` | 正在执行 |
| `SUCCESS` | 执行成功 |
| `FAILED` | 执行失败 |
| `REJECTED` | 拒绝执行 |

平台只有收到包含正确 `commandMessageId` 的回执，才能把 `device_mqtt_command` 命令记录更新为最终状态。

## 8. 联调执行顺序

### 8.1 启动网关 Agent

修改 `.env` 后重启网关服务：

```bash
docker compose up -d
docker ps
docker logs --tail 200 -f gateway-udp-proxy
```

老版本 Docker Compose 可能使用：

```bash
docker-compose up -d
docker-compose logs -f --tail=200 gateway-udp-proxy
```

网关日志预期出现：

```text
[MQTT] subscribed down topic: /default/site-001/publish-gateway-25/down/#
[MQTT-REGISTER] register published
[MQTT-HEARTBEAT] 已发布心跳
```

### 8.2 平台侧确认连接

由能 SSH 到 `192.168.1.70` 的人员执行：

```bash
cd /home/sysSjwg/platform70-deploy/extracted/monitor-platform-v1.0.0/package
docker-compose --env-file .env ps
docker exec emqx emqx ctl clients list
docker logs --tail 200 monitor-forward
```

预期：

- EMQX client 列表中有 `monitor-platform-001`。
- EMQX client 列表中有 `publish-gateway-25`。
- `monitor-forward` 日志出现：

```text
[MQTT注册] 设备注册成功: instanceId=publish-gateway-25
[MQTT心跳] 收到心跳: deviceId=publish-gateway-25
```

### 8.3 平台页面确认

访问：

```text
http://192.168.1.70/
```

检查设备列表或远程配置左侧设备树：

- 能看到 `publish-gateway-25`。
- IP 显示为 `192.168.77.25`。
- 状态为在线或最近心跳时间持续刷新。

## 9. 平台下发验证

### 9.1 首选非破坏性命令

优先使用远程修改 IP 的 dry-run 做下发链路验证，不真正改 IP：

```http
POST http://192.168.1.70/api/gateway/network/change-ip
Content-Type: application/json
Authorization: <平台登录态>
```

请求体示例：

```json
{
  "targetDeviceId": "publish-gateway-25",
  "interfaceName": "eth0",
  "newIp": "192.168.77.25",
  "prefixLength": 24,
  "applyDefaultRoute": false,
  "dryRun": true,
  "persist": false,
  "rollbackSeconds": 600,
  "changeId": "dryrun-77-25-001",
  "operator": "admin",
  "remark": "MQTT dry-run integration"
}
```

验收：

- 平台 `monitor-forward` 出现 MQTT 发布日志。
- 网关日志出现收到 `down/proxy-command`。
- 网关发布 `up/reply`。
- 平台接口返回 `data.status=SUCCESS`，或 `device_mqtt_command` 记录最终状态为 `SUCCESS`。

如果 dry-run 功能未在当前网关镜像开启，可改用已创建好的链路配置：

```http
POST http://192.168.1.70/api/chain/deploy/{chainId}
Authorization: <平台登录态>
```

该方式要求平台已存在完整链路配置，且链路节点中的目标设备 ID 与 MQTT 注册设备 ID 一致。

### 9.2 远程升级验证

远程升级只作为第二阶段验证：

1. 上传小型一键安装包。
2. 创建单设备任务，`targetDeviceIds=["publish-gateway-25"]`。
3. 启动任务。
4. 网关下载包、校验 sha256、执行测试脚本。
5. 网关通过 `up/reply` 上报 `PROCESSING` / `SUCCESS` / `FAILED`。

升级任务不应作为首次 MQTT 连通验证手段。

## 10. 现场排障

| 现象 | 优先检查 |
| --- | --- |
| 网关连不上 `192.168.1.70:1883` | 路由、防火墙、70 服务器 EMQX 是否监听、网关是否能出网到 1.70 |
| EMQX 反复只有一台网关在线 | 两台网关是否复用了同一个 `MQTT_CLIENT_ID` |
| 能连接但平台注册失败 | `MQTT_REGISTER_HOST`、`MQTT_REGISTER_PORT`、`REGISTRY_CLIENT_ID` 是否为空或不一致 |
| 平台收到心跳但页面不在线 | 设备 ID 是否已注册；心跳 `deviceId` 是否与注册 `instanceId` 一致 |
| 平台下发后网关没日志 | 网关是否订阅 `/default/site-001/{deviceId}/down/#`；平台下发的 `targetDeviceId` 是否等于网关 `deviceId` |
| 网关收到命令但无回执 | 命令执行器异常；`ReplyPublisher` 是否能拿到 MQTT 连接；回执是否带原始 `commandMessageId` |
| 回执已发但平台命令超时 | `commandMessageId` 是否等于平台下发 envelope 的 `messageId` |
| 平台直接访问不到 77 网段 | 正常；本方案依赖网关主动 MQTT 长连接，不依赖平台直连网关 |
