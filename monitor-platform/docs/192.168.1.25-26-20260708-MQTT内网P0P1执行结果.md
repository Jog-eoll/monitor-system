## 5. 生产前阻断项

1. 解密网关镜像需修复或确认 `CHANGE_SYSTEM_IP dryRun=true` 行为：dryRun 必须只做参数校验和计划生成，不得进入 `ip command check` 或真实网络命令路径。
2. 平台 `monitor-forward` 镜像需包含 `/api/mqtt/commands/control-delivery` POST 路由，否则 P1 控制命令不能验收。
3. 网关发布包需内置并执行 `mqtt_command_record` DDL/migration；本轮已手工补表，但生产交付不能依赖手工补 SQL。
4. 192.168.1.26 的 `terminal-gateway-mysql` 持续 Restarting，需清理旧容器或修复数据目录；即使当前网关健康，也不应带该异常交付。

## 6. 推荐下一轮顺序

1. 重新构建并部署解密网关镜像，复测 `CHANGE_SYSTEM_IP dryRun`。
2. 重新构建并部署平台 `monitor-forward` 镜像，确认 `control-delivery` POST 路由存在。
3. 将 `mqtt_command_record` DDL 纳入部署脚本或 Liquibase/初始化流程，重新在干净库验证。
4. 重跑 P0 全量：连接、注册、心跳、`QUERY_STATUS/NOOP/ECHO`、超时、重复 messageId、dryRun。
5. P0 通过后再跑 P1：链路部署、控制投递、内容投递、截图、升级 verify-only、稳定性。
