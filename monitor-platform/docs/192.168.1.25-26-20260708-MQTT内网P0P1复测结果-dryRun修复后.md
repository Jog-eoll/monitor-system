## 4. P1 复测

### 4.1 链路部署 / 代理规则

平台链路：`chainId=49`，链路节点为 `192.168.1.168 -> 192.168.1.25 -> 192.168.1.26 -> 192.168.113.88`。

| 路径 | 结果 | 证据 |
| --- | --- | --- |
| 平台 API `POST /chain/deploy/49` | 失败/超时 | 命令 `9e4a13e82a4740a9a896d88b8c8d1aea` 发往 `/default/site-001/publish-001/down/proxy-command`，实际在线 MQTT clientId 是 `publish-gateway-25`，平台等待回执超时。 |
| 直接 MQTT 到正确 topic | 成功 | `p1chain87382f10e39f4d52a7999739` 发往 `/default/site-001/publish-gateway-25/down/proxy-command`，发布网关收到 `CHAIN_DEPLOY`，HTTP 转发到 `192.168.1.26:8093/udp-proxy/config` 返回 200，并上报 `SUCCESS`。 |
| 26 规则状态 | 成功落地 | `GET /udp-proxy/rules/running` 返回 `["49_terminal","49_terminal"]`，`GET /udp-proxy/status/49_terminal` 返回 `RUNNING`。 |

问题：平台链路下发不能只用 `task_chain_node.deviceId` 当 MQTT 路由 ID，需要映射到当前注册的 MQTT client/device ID。

### 4.2 控制命令投递

| 用例 | messageId | 结果 |

## 5. 当前生产交付缺口

P0 可以作为已通过记录。P1 生产交付前至少补齐：

1. 修复 `/chain/deploy/{chainId}` 的 MQTT 路由 ID 映射，不能用不在线的 `publish-001` topic；需要从注册/心跳/统一设备表映射到 `publish-gateway-25`。
2. 修复 `CONTROL_DELIVERY` 明文兼容或加密包生成契约，确保至少一个无破坏控制命令通过 publish-gateway 路径成功。
3. 准备可复现的小文件内容投递素材：MinIO object、SHA256、加密任务包或明确的明文兼容包，然后跑成功和失败两类用例。
4. 给 `board_88` 或对应 manufacturer 配置截图策略，或明确截图不支持并调整 P1 验收范围。
5. 26 成功 verify-only 前，先确认 `upgrade.executor.enabled=false` 或提供 harmless 安装脚本；否则只允许跑失败语义。
6. 安排窗口执行 EMQX、25 发布网关、26 终端网关、monitor-forward 的重启恢复测试。
