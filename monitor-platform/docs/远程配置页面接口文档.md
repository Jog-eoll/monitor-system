# 远程配置页面接口文档

本文档供前端接入“远程配置”页面使用，覆盖左侧目标设备选择、安装包升级、历史版本、版本回滚。`一键重启` 暂不纳入本次接入。

## 1. 接入约定

### 1.1 服务路径

后端 Controller 原始路径如下：

- 设备列表：`/device/unified`
- 远程升级：`/upgrade`

部署环境通过 Nginx/Gateway 转发时，可使用 `/api` 前缀，例如：

- `GET /api/device/unified/page`
- `POST /api/upgrade/packages/upload`

Nginx 当前会将 `/api/xxx` 重写为 `/xxx` 后转发到 `monitor-gateway:8060`。

### 1.2 通用响应

除文件下载外，接口统一返回：

```json
{
  "code": 200,
  "msg": "操作成功",
  "time": 1782540011454,
  "data": {}
}
```

前端判断规则：

- `code === 200`：平台接口调用成功。
- `code !== 200`：平台接口失败，展示 `msg`。
- 升级命令是否真正执行成功，需要继续看任务/设备状态字段。

### 1.3 固定枚举

包类型本页面只保留一种：

| 字段值 | 展示名 | 说明 |
| --- | --- | --- |
| `installer` | 一键安装包 | 上传、筛选、创建任务时统一使用该值 |

设备类型建议先接入：

| 字段值 | 展示名 | 页面位置 |
| --- | --- | --- |
| `publish_gateway` | 加密网关 | 左侧“加密网关” |
| `terminal_encrypt_gateway` | 解密网关 | 左侧“解密网关” |

目标设备编号统一使用 `targetDeviceId`，对应设备接口返回的 `deviceId`。不要在前端新增 `gatewayDeviceId` 这类强绑定字段。

## 2. 页面调用流程

### 2.1 页面初始化

1. 调用 `GET /device/unified/page` 加载左侧设备。
2. 根据页签传入 `deviceType=publish_gateway` 或 `deviceType=terminal_encrypt_gateway`。
3. 前端本地维护选中设备数组 `targetDeviceIds`。

### 2.2 安装包升级

1. 用户选择一个或多个目标设备。
2. 上传一键安装包：`POST /upgrade/packages/upload`。
3. 创建升级任务：`POST /upgrade/tasks`。
4. 启动任务：`POST /upgrade/tasks/{taskId}/start`。
5. 轮询任务和设备明细：`GET /upgrade/tasks/{taskId}`、`GET /upgrade/tasks/{taskId}/devices`。
6. 任务结束后刷新历史版本：`GET /upgrade/devices/{targetDeviceId}/versions`。

### 2.3 历史版本

1. 用户选择左侧单个设备。
2. 调用 `GET /upgrade/devices/{targetDeviceId}/versions` 渲染时间线。
3. 点击“回滚所选版本”时调用 `POST /upgrade/devices/{targetDeviceId}/rollback`。

## 3. 目标设备列表

### 3.1 分页查询设备

```http
GET /device/unified/page?pageNum=1&pageSize=50&deviceType=publish_gateway&status=在线&keyword=192.168.1.25
Authorization: <平台登录态>
```

请求参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `pageNum` | number | 否 | 页码，默认 `1` |
| `pageSize` | number | 否 | 每页数量，默认 `10`，远程配置建议 `50` |
| `deviceType` | string | 否 | 设备类型，见 1.3 |
| `status` | string | 否 | 状态筛选，例如 `在线`、`离线` |
| `keyword` | string | 否 | 名称、设备编号、IP 模糊搜索 |

响应 `data` 为 MyBatis Plus 分页结构：

```json
{
  "records": [
    {
      "deviceId": "publish-gateway-25",
      "deviceName": "加密网关",
      "deviceType": "publish_gateway",
      "deviceTypeLabel": "发布端加密网关",
      "ipAddress": "192.168.1.25",
      "port": 8093,
      "status": "在线",
      "version": "v2.4.1",
      "lastOnlineTime": "2026-07-02 10:20:00",
      "remark": null
    }
  ],
  "total": 1,
  "size": 50,
  "current": 1
}
```

前端字段映射：

| 页面字段 | 接口字段 | 说明 |
| --- | --- | --- |
| 设备唯一值 | `deviceId` | 提交升级任务时作为 `targetDeviceId` |
| 设备名称 | `deviceName` | 没有名称时可展示 `deviceTypeLabel` |
| IP | `ipAddress` | 左侧主标题优先展示 |
| 在线状态 | `status` | `在线`/`正常` 可视为在线 |
| 当前版本 | `version` | 左侧可选展示；历史页以升级记录为准 |

## 4. 安装包升级接口

### 4.1 上传安装包

```http
POST /upgrade/packages/upload
Content-Type: multipart/form-data
Authorization: <平台登录态>
```

表单参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | file | 是 | 一键安装包文件 |
| `packageName` | string | 是 | 包名称，建议默认取文件名 |
| `packageType` | string | 是 | 固定传 `installer` |
| `deviceType` | string | 是 | 目标设备类型 |
| `targetVersion` | string | 是 | 目标版本，例如 `v2.4.1` |
| `remark` | string | 否 | 升级说明 |

响应 `data`：

```json
{
  "id": 12,
  "packageCode": "PKG-20260702102000-abcd1234",
  "packageName": "publish-gateway-v2.4.1.zip",
  "packageType": "installer",
  "deviceType": "publish_gateway",
  "targetVersion": "v2.4.1",
  "storageType": "minio",
  "objectName": "upgrade/publish-gateway-v2.4.1.zip",
  "downloadUrl": "http://...",
  "sha256": "....",
  "fileSize": 10485760,
  "status": "ACTIVE",
  "remark": "修复复制锁有延时",
  "createTime": "2026-07-02 10:20:00"
}
```

### 4.2 查询安装包列表

```http
GET /upgrade/packages?deviceType=publish_gateway&packageType=installer
Authorization: <平台登录态>
```

响应 `data` 为安装包数组，字段同 4.1。用途：

- 页面上传后刷新包列表。
- 创建任务前让前端确认 `packageId`。
- 历史版本回滚时校验包是否仍存在。

### 4.3 创建升级任务

```http
POST /upgrade/tasks
Content-Type: application/json
Authorization: <平台登录态>
```

请求体：

```json
{
  "taskName": "publish-gateway-v2.4.1 批量升级",
  "packageId": 12,
  "packageName": "publish-gateway-v2.4.1.zip",
  "targetDeviceIds": ["publish-gateway-25"],
  "rollbackEnabled": true,
  "timeoutSeconds": 1800,
  "operator": "admin",
  "remark": "远程配置页面发起"
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `taskName` | string | 否 | 任务名称；不传时后端可按包名生成 |
| `packageId` | number | 是 | 4.1/4.2 返回的安装包 ID |
| `packageName` | string | 否 | 冗余展示字段 |
| `targetDeviceIds` | string[] | 是 | 左侧选中设备 `deviceId` 数组 |
| `rollbackEnabled` | boolean | 否 | 是否允许后续回滚，建议默认 `true` |
| `timeoutSeconds` | number | 否 | 超时时间，默认 `1800` |
| `operator` | string | 否 | 操作人账号 |
| `remark` | string | 否 | 升级说明 |

响应 `data`：

```json
{
  "id": 31,
  "taskCode": "UPG-20260702103000-abcd1234",
  "taskName": "publish-gateway-v2.4.1 批量升级",
  "packageId": 12,
  "packageCode": "PKG-20260702102000-abcd1234",
  "packageType": "installer",
  "targetVersion": "v2.4.1",
  "status": "CREATED",
  "totalCount": 1,
  "successCount": 0,
  "failedCount": 0,
  "timeoutCount": 0,
  "rollbackEnabled": true,
  "timeoutSeconds": 1800,
  "operator": "admin",
  "createTime": "2026-07-02 10:30:00"
}
```

### 4.4 启动升级任务

```http
POST /upgrade/tasks/{taskId}/start
Content-Type: application/json
Authorization: <平台登录态>
```

请求体：

```json
{
  "waitForResult": false
}
```

说明：

- 批量升级固定传 `false`，避免 HTTP 请求长时间阻塞。
- 启动成功只代表平台已开始下发 MQTT 命令，不代表设备已升级完成。

响应 `data` 为启动结果 Map，至少关注：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `taskId` | number | 任务 ID |
| `taskCode` | string | 任务编号 |
| `status` | string | 启动后的任务状态 |
| `total` | number | 下发设备数 |
| `success` | number | 同步下发成功数 |
| `failed` | number | 同步下发失败数 |
| `results` | array | 每台设备下发结果 |

### 4.5 查询任务概览

```http
GET /upgrade/tasks/{taskId}
Authorization: <平台登录态>
```

响应 `data` 字段同 4.3。前端用于顶部“等待状态”和整体进度：

```text
整体进度 = (successCount + failedCount + timeoutCount) / totalCount
```

### 4.6 查询任务设备明细

```http
GET /upgrade/tasks/{taskId}/devices
Authorization: <平台登录态>
```

响应 `data`：

```json
[
  {
    "id": 101,
    "taskId": 31,
    "taskCode": "UPG-20260702103000-abcd1234",
    "targetDeviceId": "publish-gateway-25",
    "deviceType": "publish_gateway",
    "currentVersion": "v2.4.0",
    "targetVersion": "v2.4.1",
    "mqttCommandId": 88,
    "mqttMessageId": "msg-xxx",
    "status": "PROCESSING",
    "stage": "DOWNLOAD",
    "progress": 45,
    "errorMessage": null,
    "commandTime": "2026-07-02 10:30:05",
    "ackTime": "2026-07-02 10:30:08",
    "finishTime": null
  }
]
```

设备状态：

| 状态 | 展示文案 | 说明 |
| --- | --- | --- |
| `CREATED` | 待下发 | 任务已创建设备明细 |
| `PUBLISHED` | 已下发 | MQTT 命令已发出 |
| `PROCESSING` | 升级中 | 设备已回执处理中 |
| `SUCCESS` | 成功 | 设备升级完成 |
| `FAILED` | 失败 | 设备执行失败，展示 `errorMessage` |
| `TIMEOUT` | 超时 | 超过 `timeoutSeconds` 未完成 |

前端建议每 `2-3` 秒轮询一次，遇到 `SUCCESS`、`FAILED`、`PARTIAL_FAILED` 或全部设备进入终态后停止轮询。

## 5. 历史版本接口

### 5.1 查询设备历史版本

```http
GET /upgrade/devices/{targetDeviceId}/versions
Authorization: <平台登录态>
```

响应 `data`：

```json
{
  "targetDeviceId": "publish-gateway-25",
  "currentVersion": "v2.4.1",
  "total": 2,
  "records": [
    {
      "version": "v2.4.1",
      "status": "SUCCESS",
      "packageId": 12,
      "packageName": "publish-gateway-v2.4.1.zip",
      "taskId": 31,
      "taskName": "publish-gateway-v2.4.1 批量升级",
      "packageType": "installer",
      "fileSize": 10485760,
      "sha256": "....",
      "installedAt": "2026-05-28 14:20:00",
      "durationText": "8 分钟",
      "operator": "admin",
      "rollbackable": true,
      "remark": "修复复制锁有延时"
    }
  ]
}
```

页面字段映射：

| 页面字段 | 接口字段 | 说明 |
| --- | --- | --- |
| 时间点 | `installedAt` | 时间线左侧时间 |
| 版本号 | `version` | 卡片主标题 |
| 当前运行 | `version === currentVersion` | 前端自行计算标签 |
| 安装包 | `packageName` | 卡片第二行 |
| 耗时 | `durationText` | 为空时展示 `-` |
| 操作人 | `operator` | 为空时展示 `-` |
| 说明 | `remark` | 卡片说明 |
| 可回滚 | `rollbackable` | 控制“回滚所选版本”按钮 |

注意：当前后端只返回成功安装记录，`status` 通常为 `SUCCESS`。截图里的“已被回滚”属于展示态，当前接口没有单独字段；前端可以先按 `version !== currentVersion` 展示为“历史版本”，不要强行展示“已被回滚”。

### 5.2 导入历史版本

用于初始化已有设备的历史版本，不建议普通用户频繁使用。

```http
POST /upgrade/devices/{targetDeviceId}/versions/import
Content-Type: application/json
Authorization: <平台登录态>
```

请求体：

```json
{
  "version": "v2.4.0",
  "packageId": 11,
  "packageName": "publish-gateway-v2.4.0.zip",
  "installedAt": "2026-04-12 09:15:00",
  "operator": "admin",
  "remark": "历史版本补录"
}
```

### 5.3 回滚到指定版本

```http
POST /upgrade/devices/{targetDeviceId}/rollback
Content-Type: application/json
Authorization: <平台登录态>
```

请求体：

```json
{
  "packageId": 11,
  "targetVersion": "v2.4.0",
  "operator": "admin",
  "remark": "页面发起版本回滚"
}
```

说明：

- `packageId` 必填，来自历史版本记录。
- 后端会按该安装包重新创建一个单设备升级任务，并立即启动。
- 返回结构与 `POST /upgrade/tasks/{taskId}/start` 一致。

## 6. 前端状态映射

任务状态：

| 状态 | 展示文案 |
| --- | --- |
| `CREATED` | 待启动 |
| `RUNNING` | 升级中 |
| `SUCCESS` | 全部成功 |
| `PARTIAL_FAILED` | 部分失败 |
| `FAILED` | 失败 |

安装包状态：

| 状态 | 展示文案 |
| --- | --- |
| `ACTIVE` | 可用 |

历史版本展示标签建议：

| 条件 | 展示文案 |
| --- | --- |
| `record.version === currentVersion` | 当前运行 |
| `record.rollbackable === true` 且非当前版本 | 可回滚 |
| `record.rollbackable !== true` 且非当前版本 | 历史版本 |

## 7. 本页面需要补充或确认的点

现有接口已覆盖：

- 左侧设备分页、搜索、状态筛选：`GET /device/unified/page`
- 上传一键安装包：`POST /upgrade/packages/upload`
- 安装包列表：`GET /upgrade/packages`
- 创建升级任务：`POST /upgrade/tasks`
- 启动升级任务：`POST /upgrade/tasks/{taskId}/start`
- 查询任务概览：`GET /upgrade/tasks/{taskId}`
- 查询设备升级明细：`GET /upgrade/tasks/{taskId}/devices`
- 查询历史版本：`GET /upgrade/devices/{targetDeviceId}/versions`
- 导入历史版本：`POST /upgrade/devices/{targetDeviceId}/versions/import`
- 回滚版本：`POST /upgrade/devices/{targetDeviceId}/rollback`

建议后续增强但本次不是阻断项：

| 能力 | 建议 | 原因 |
| --- | --- | --- |
| 回滚记录面板 | 增加 `GET /upgrade/devices/{targetDeviceId}/rollback-records`，或在 versions 响应中增加 `rollbackRecords` | 截图右侧“可选记录/回滚记录”目前没有独立字段 |
| 历史版本状态 | 增加 `displayStatus` 或 `versionStatus`，例如 `CURRENT/RUNNING/ROLLED_BACK/HISTORY` | 避免前端靠 `currentVersion` 自行推断 |
| 设备在线枚举 | 统一后端返回 `ONLINE/OFFLINE`，同时保留中文状态 | 当前设备状态存在 `在线/正常` 等多种中文值 |
| 安装包分页 | `GET /upgrade/packages` 增加分页参数 | 安装包数量变多后避免一次性返回过大列表 |
