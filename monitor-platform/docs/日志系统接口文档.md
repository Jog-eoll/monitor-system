# 日志系统接口文档

本文档供前端页面接入"日志系统"功能使用。前端发布审计主页面只需调用 **发布审计聚合接口 `/log/audit/page`**；其它接口作为明细查询、排障联动或历史兼容参考，涵盖 **发布审计日志**、**发布日志**、**操作日志**、**诊断事件**、**链路日志** 和 **系统用户日志** 六类接口。

---

## 通用说明

### 响应格式

所有接口统一返回：

```json
{
  "code": 200,
  "msg": "处理成功",
  "time": 1782540011454,
  "data": {}
}
```

### 通用状态码

| code | 含义 |
| --- | --- |
| 200 | 平台接口调用成功 |
| 非200 | 平台接口调用失败，展示 `msg` 错误信息 |

### 登录态

所有接口需要携带平台登录态，通过 `Authorization` 请求头传递。

### 分页参数

分页查询接口继承 `PageDTO`，请求体需传入：

| 字段 | 类型 | 必填 | 说明 | JSON别名 |
| --- | --- | --- | --- | --- |
| `current` | number | 否 | 当前页码，从1开始 | `currentPage` |
| `size` | number | 否 | 每页条数 | `pageSize` |

分页响应以 `records`、`total`、`current`、`size`、`pages` 为核心字段。发布审计聚合接口 `/log/audit/page` 额外兼容历史分页字段 `page`、`pageSize`、`pageNum`，并保留 MyBatis-Plus 常见分页字段：

```json
{
  "code": 200,
  "data": {
    "records": [...],
    "total": 100,
    "size": 20,
    "current": 1,
    "orders": [],
    "optimizeCountSql": true,
    "searchCount": true,
    "maxLimit": null,
    "countId": null,
    "pages": 5,
    "page": 1,
    "pageSize": 20,
    "pageNum": 1
  }
}
```

# 一、发布审计日志

> 查询发布审计聚合记录，用于在一条列表数据中展示“谁操作了什么、发布了什么内容、客户端签名/验签是否通过、网关是否上报、内容是否合规”。  
> 该接口为查询接口，不写入日志。数据以 `t_content_monitor` 发布内容记录为主表，关联 `diagnostic_event_log`、`sys_user_log`、`alarm_record`、`task_chain_config` 汇总展示。

## 1.1 分页查询发布审计日志

```http
POST /log/audit/page
Content-Type: application/json
Authorization: <沿用平台登录态>
```

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `current` | number | 否 | 当前页码 |
| `size` | number | 否 | 每页条数 |
| `startTime` | string | 否 | 开始时间，格式 `yyyy-MM-dd HH:mm:ss` |
| `endTime` | string | 否 | 结束时间，格式 `yyyy-MM-dd HH:mm:ss` |
| `chainId` | number | 否 | 链路 ID |
| `chainCode` | string | 否 | 链路编码 |
| `sourceIp` | string | 否 | 来源 IP |
| `boardIp` | string | 否 | 板卡 IP |
| `contentType` | string | 否 | 内容类型 |
| `status` | string | 否 | 内容原始状态，对应 `t_content_monitor.status`，常用值：`pending`、`normal`、`violation` |
| `complianceStatus` | string | 否 | 聚合合规状态：`pending` 待审核、`normal` 合规、`violation` 违规 |
| `operatorName` | string | 否 | 操作人名称，匹配客户端签名/验签操作日志中的 `actor_name` |
| `clientIp` | string | 否 | 客户端 IP，兼容操作日志页面筛选 |
| `ip` | string | 否 | IP 筛选别名，作用同 `clientIp` |
| `type` | string | 否 | 日志类型，兼容操作日志页面；当前聚合数据支持 `operation`/`操作`，传 `system`/`系统` 时本接口暂不返回聚合数据 |
| `logType` | string | 否 | 日志类型别名，作用同 `type` |
| `actType` | string | 否 | 操作类型，支持 `publish`/`发布`、`sign`/`签名`、`verify`/`验签`、`gateway_report`/`网关上报`、`audit`/`内容审核` |
| `operationType` | string | 否 | 操作类型别名，作用同 `actType` |
| `actModule` | string | 否 | 操作模块，支持 `publish_audit`/`发布审计`、`publish`/`发布`、`content`/`内容` |
| `operationModule` | string | 否 | 操作模块别名，作用同 `actModule` |
| `resultStatus` | string | 否 | 环节结果状态：`success`、`fail`、`pending`，匹配签名、验签、网关上报或内容合规结果 |
| `keyword` | string | 否 | 关键字搜索，匹配内容 ID、文件名、描述、文本内容、审计原因、链路名称、操作人 |

### 请求示例

```json
{
  "current": 1,
  "size": 20,
  "startTime": "2026-06-01 00:00:00",
  "endTime": "2026-06-30 23:59:59",
  "type": "operation",
  "actType": "audit",
  "actModule": "publish_audit",
  "chainCode": "CHAIN-001",
  "contentType": "image",
  "complianceStatus": "violation",
  "operatorName": "admin",
  "resultStatus": "fail",
  "keyword": "测试图片"
}
```

### 响应

分页返回发布审计聚合记录。`data` 分页字段统一为：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `records` | array | 当前页发布审计聚合记录 |
| `total` | number | 总记录数 |
| `size` | number | 每页条数，兼容 MyBatis-Plus |
| `current` | number | 当前页码，兼容 MyBatis-Plus |
| `orders` | array | 排序字段，当前通常为空数组 |
| `optimizeCountSql` | boolean | MyBatis-Plus 计数 SQL 优化标识 |
| `searchCount` | boolean | MyBatis-Plus 是否执行总数查询标识 |
| `maxLimit` | number/null | MyBatis-Plus 单页上限 |
| `countId` | string/null | MyBatis-Plus 自定义 countId |
| `pages` | number | 总页数 |
| `page` | number | 当前页码，兼容历史分页接口 |
| `pageSize` | number | 每页条数，兼容历史分页接口 |
| `pageNum` | number | 当前页码，兼容使用 `pageNum/pageSize` 的分页接口 |

`records` 中每条数据为 `Map<String, Object>`，核心字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | number | 发布内容记录主键 |
| `serialNo` | number | 页面序号，后端按分页位置生成 |
| `eventTime` | string | 内容接收/发布记录时间，来源 `t_content_monitor.receive_time` |
| `operationTime` | string | 操作时间，页面字段，当前等同 `eventTime` |
| `createTime` | string | 创建时间，兼容操作日志页面，当前等同 `eventTime` |
| `operatorName` | string | 操作人，优先取客户端签名/验签操作人，取不到时回退到网关 ID 或来源 IP |
| `clientIp` | string | 客户端操作 IP，优先取签名/验签日志中的客户端 IP |
| `ip` | string | 页面 IP 字段，优先取 `clientIp`，再取 `sourceIp`、`boardIp` |
| `type` | string | 日志类型，当前固定为 `operation` |
| `logType` | string | 日志类型，当前固定为 `operation` |
| `logTypeName` | string | 日志类型中文名，当前为 `操作` |
| `actType` | string | 操作类型编码：`publish`、`sign`、`verify`、`gateway_report`、`audit` |
| `operationType` | string | 操作类型编码，作用同 `actType` |
| `operationTypeName` | string | 操作类型中文名：发布、签名、验签、网关上报、内容审核 |
| `actModule` | string | 操作模块编码，当前为 `publish_audit` |
| `operationModule` | string | 操作模块编码，当前为 `publish_audit` |
| `operationModuleName` | string | 操作模块中文名，当前为 `发布审计` |
| `actAction` | string | 操作功能，页面字段，当前等同 `action` |
| `operationFunction` | string | 操作功能，页面字段，当前等同 `action` |
| `result` | string | 页面结果编码：`success`、`fail`、`pending` |
| `resultName` | string | 页面结果中文名：成功、失败、待处理 |
| `actResult` | string | 兼容操作日志结果码：`200` 成功、`500` 失败、`102` 待处理 |
| `detailAvailable` | boolean | 是否具备详情联动数据 |
| `action` | string | 聚合动作描述，如 `客户端验签失败`、`发布内容违规`、`发布内容待审核`、`发布内容通过` |
| `traceId` | string | 诊断事件链路 ID，用于联动 `POST /log/event/timeline` 查看完整时间线 |
| `contentId` | string | 内容业务 ID |
| `contentType` | string | 内容类型，如 `text`、`image`、`video` |
| `fileName` | string | 文件名，文本内容可能为空 |
| `contentSummary` | string | 内容摘要。文本取 `data` 前 200 字，图片/视频取 `description` 前 200 字 |
| `minioPath` | string | 文件在 MinIO 中的对象路径 |
| `fileUrl` | string | 文件访问地址，由后端根据 `minio.endpoint`、bucket 和 `minioPath` 拼接；无文件或配置缺失时为 `null` |
| `previewUrl` | string | 前端预览地址，当前与 `fileUrl` 一致 |
| `downloadUrl` | string | 前端下载地址，当前与 `fileUrl` 一致 |
| `thumbnail` | string | 缩略图地址或缩略图路径，按实际入库值返回 |
| `chainId` | number | 链路 ID |
| `chainCode` | string | 链路编码 |
| `chainName` | string | 链路名称 |
| `gatewayId` | string | 加密网关/发布网关标识 |
| `sourceIp` | string | 来源 IP |
| `boardIp` | string | 情报板 IP |
| `boardPort` | number | 情报板端口 |
| `playBatchId` | string | 播放批次 ID |
| `playBatchSeq` | number | 播放批次序号 |
| `playBatchSize` | number | 播放批次总数 |
| `signStatus` | string | 客户端签名结果：`success`、`fail` 或 `null` |
| `verifyStatus` | string | 客户端验签结果：`success`、`fail` 或 `null` |
| `gatewayReportStatus` | string | 加密网关发布内容上报结果：`success`、`fail` 或 `null` |
| `complianceStatus` | string | 聚合合规状态：`pending`、`normal`、`violation` |
| `contentStatus` | string | 内容原始状态，来源 `t_content_monitor.status` |
| `isViolation` | number | 是否违规：`1` 违规、`0` 不违规、`null` 未判定 |
| `violationType` | string | 违规类型 |
| `confidence` | number | 审计置信度 |
| `reason` | string | 审计原因或说明 |
| `errorMessage` | string | 内容处理异常信息 |
| `alarmId` | number | 关联告警 ID |
| `alarmType` | string | 告警类型 |
| `alarmLevel` | string | 告警级别 |
| `alarmStatus` | string | 告警处理状态 |
| `alarmDetail` | string | 告警/违规详情 |

### 数据来源与匹配规则

| 展示内容 | 主要来源 | 说明 |
| --- | --- | --- |
| 发布内容、内容摘要、合规结果、MinIO 对象路径 | `t_content_monitor` | 以内容发布记录为主表，每条发布内容对应一条审计聚合记录 |
| 客户端签名状态 | `diagnostic_event_log` / `sys_user_log` | 诊断事件类型匹配 `CLIENT_CONTENT_SIGNED`、`CLIENT_PUBLISH_PERMIT_SIGNED`；操作日志匹配 `act_type=sign` |
| 客户端验签状态 | `diagnostic_event_log` / `sys_user_log` | 诊断事件类型匹配 `CLIENT_PACKAGE_VERIFIED`；操作日志匹配 `act_type=verify` |
| 加密网关发布内容上报状态 | `diagnostic_event_log` | 诊断事件类型匹配 `GATEWAY_CONTENT_REPORTED`、`GATEWAY_CONTENT_REPORT_FAILED` |
| 链路名称和链路编码 | `task_chain_config` | 通过 `chain_id` 关联 |
| 违规告警信息 | `alarm_record` | 通过 `content_id` 关联最近一条告警记录 |

文件访问地址由服务端根据 `minio.endpoint`、bucket 和 `minioPath` 拼接。bucket 优先读取 `log.audit.minio-bucket`，未配置时使用 `minio.bucket`，再未配置时默认 `monitor-content`。

### 前端展示建议

1. 操作日志页面表格字段映射：序号=`serialNo`，操作时间=`operationTime`，操作人=`operatorName`，日志类型=`logTypeName`，操作类型=`operationTypeName`，操作模块=`operationModuleName`，操作功能=`operationFunction`，IP=`ip`，结果=`resultName`。
2. 详情或扩展列可展示 `contentSummary`、`complianceStatus`、`signStatus`、`verifyStatus`、`gatewayReportStatus`。
3. 文件预览优先使用 `previewUrl`；下载按钮使用 `downloadUrl`；仅需展示原始对象路径时使用 `minioPath`。
4. `fileUrl`、`previewUrl`、`downloadUrl` 可能为 `null`，前端需隐藏预览/下载按钮或展示“暂无文件”。
5. 点击 `traceId` 可联动调用 `POST /log/event/timeline` 查看客户端签名、验签、网关上报等完整链路。
